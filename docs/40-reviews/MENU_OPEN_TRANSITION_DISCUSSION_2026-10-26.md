# 2D探索から携帯端末メニューを開く演出：総合担当の意見

日付: 2026-11-06 / 総合担当（Claude Code）
相談: `docs/30-planning/HANDOFF_MENU_OPEN_TRANSITION_2026-10-26.md`（メニュー担当 Codex）
状態: **意見・推奨のみ**。コード・素材・Unity・HTML は変えていない。決めるのは原作者。

表記: **【観察】**＝実物（コード・画像）で確かめた / **【推測】**＝確かめていない見込み / **【未確認】**＝確かめられていない。**〔判断〕**＝原作者が決めること / **〔技術〕**＝技術上の注意。

## 0. 結論（推奨）

**修正版（③＋小さな浮き上がり）を土台にして、最後の「枠だけ薄くなる」を「寄って、枠が画面の外へ抜ける」に替える**のをすすめる（以下「③＋寄り」）。

1. 探索画面はそのまま（カメラも視点も動かさない）。少し暗くして操作のボタンを隠す。
2. 枠つきの端末が画面の真ん中に、小さく浮いて現れる（修正版の 02 と同じ大きさ）。
3. 端末ごと大きくなり（寄る）、**中の画面がちょうど画面いっぱいになったところで止まる**。そのとき枠は画面の外に出ていて、もう見えない。
4. 枠なしのホームで操作する。閉じるときは逆（または短い切り替え）。

理由:
- 【観察】端末の原本（`横向きフレーム素材.png`）の内窓は 1391.5×643 で、844×390 と同じ比率（2.16）。だから「中の画面が画面いっぱいになるまで均一に拡大する」だけで、**歪まず、文字の大きさも途中から最後まで連続**する（拡大の倍率は約 0.74 → 1.0。再レビューで測った「枠ありの縮小率 0.736」と同じ）。§6 の相談への答えにもなる。
- 枠を薄くする（修正版の 03）と、相談書の懸念どおり「ただのフェード」に見えやすい。寄って枠が外へ抜けると、**端末をのぞき込んだ**感じが出る。しかも動きは「真ん中で拡大するだけ」なので、①のような視点の切り替え（一人称になったように見える）は起きない。
- 横から見る 2D の探索で、端末を「キャラが見ている画面をプレイヤーにも見せる」形で正面に出すのは、ゲームでよくある見せ方で、不自然ではない【推測】（キャラが手に持つ絵がなくても伝わる）。

## 1. 案ごとの比べ（相談 §7-1）

| 案 | 横視点の 2D との合い方 | 端末らしさ | テンポ | 手間 |
|---|---|---|---|---|
| ① 構えて寄る | 傾いて下から上がる動きは「キャラの目線＝一人称」に見えやすい。2D の横視点から急に切り替わる【推測】 | とても強い | 0.5 秒。毎回だと少し重い | 傾き・ぼかしなど多い |
| ② ボタンから広がる | 合うが、アプリが開くふつうの動きに見える | 弱い | 軽い | 少ない。ただし入口の位置に縛られる |
| ③ 枠から溶ける | 合う（視点を動かさない） | 中（控えめだとただのフェード） | 軽い | 少ない |
| 修正版（③＋浮き上がり） | 合う | 中〜強 | 0.36 秒 | 少ない |
| **③＋寄り（推奨）** | 合う | 強い（のぞき込む感じ） | 0.35 秒前後 | 少ない（拡大1つ＋暗さ） |

**キャラが端末を取り出すポーズ**〔判断〕: 必須ではない。あると「アルシェが端末を見た」がはっきりするが、SD の素材（取り出す・見る絵）が要り、毎回の操作で少し待たされる。**まず無しで作り、あとから足せる形**（開く最初の 0.1 秒に SD が立ち止まって端末を見る絵を差し込むだけ）をすすめる。演出そのものは作り直さなくてよい。

## 2. メニューを開く入口（相談 §7-2）

【観察】今の Unity の 2D 探索（公開版の「探索（2Dの試し）」と同じ作り）:
- 歩く ◀ ▶ は画面の左右の真ん中の高さ。右下に仮の「設定」「セーブ」「最初へ」（総合担当が置いた仮の物。メニューができたら外すと決めてある）。
- キーボードは ← → / A D で歩く、Enter / Space で出口・調べる。

提案〔判断〕:
- **右下に端末のボタン1つ**（今の仮の3つの場所）。スマホを横に持つと右手の親指が届く。◀ ▶ とも離れている。
- 見た目は端末のマーク（太陽盤の小さな印など）。文字は無しか「端末」。
- キーボードは **Esc**（閉じるのも Esc）。ゲームパッドは後で。
- 開ける時: **自由に歩いている時だけ**の案。会話中・場所の移り変わり・決まった歩き（演出）の間は開けない（今のセーブと同じ決まり【観察】: 会話中・移動中はセーブできない作りにしてある）。**戦闘中は戦闘の画面に別の決まりがあるので、今回は決めない**（相談書どおり）。

## 3. Unity で作るときの影響と、くらべる試作（相談 §7-3）

【観察】携帯端末のホームは今 **HTML の試作だけ**で、Unity にはまだない（太陽盤・アプリ・予報の帯は Unity の画面としては未作成）。

- **くらべる試作（すすめ）**: Unity ではなく、**メニュー担当の HTML の試作の中**で、探索画面の画像を後ろに置き、ボタンを押すと ③＋寄り／修正版／① が切り替わって動くページを作る。スマホのブラウザでも見られる。原作者が並べてくらべやすい。目安: 半日ほど（メニュー担当）【推測】。
- **Unity に入れるとき**（正式採用のあと）:
  1. ホームを Unity の画面（uGUI）に作り直す。これが大きい（数日）【推測】。太陽盤の炎の APNG はコマを並べた絵に直す必要がある（前回のレビューどおり）。
  2. 開く演出そのものは小さい（半日ほど）【推測】: ホームの画面をまるごと1つの入れ物にして、拡大と暗さを時間で動かすだけ。
  3. 探索側: 開いている間は `Explore2DController` を Busy 扱いにし、`Corridor2DView` を Locked にする（セーブの画面と同じ止め方。§4）。
- 影響する所【観察】: `Corridor2DView`（入力）、`Explore2DController`（開ける時の判定）、`StartMenu`（今の仮のボタン）、セーブ（`SaveMenu`）・設定（`SettingsMenu`）はホームのコマンドから呼ぶ形に替える（つなぎ方は `FOUNDATION_GAPS_2026-10-08.md` §8・§10 に書いてある）。

## 4. 入力・連打・閉じたあと（相談 §7-4）

【観察】今の 2D 探索の歩き:
- 画面の ◀ ▶ は「押している間」を覚えていて、指を離した（PointerUp）か外れた（PointerExit）ときに止まる。
- キーボードは毎フレーム「押されているか」を見る。セーブの画面が開いている間は、キーボードで歩かない・調べないように止めてある。
- `Locked` の間は歩かないが、「押している間」の記録は消さない。

注意〔技術〕:
- **開く瞬間に「押している間」を消す**（◀ ▶ の記録・押した所へ歩く途中も止める）。消さないと、メニューを閉じたあとに指を離していないことになり、**勝手に歩き出す**おそれ【推測】。
- **閉じたあとは、キーを一度離すまで歩かない**（Esc で閉じたあと、押しっぱなしの → で急に動かないように）。
- 開いている途中の連打: もう一度押したら**演出を飛ばして開き終える**。開く途中で閉じたら、**今の位置から逆に戻す**（最初からやり直さない）。
- メニューの中では、最初に選ばれているのは今の太陽盤の選択（出撃）のままでよい。閉じたら探索へフォーカスを返す。
- 音: 開く・閉じるで1つずつ。音はまだ入っていない（設定の音量だけある）ので、入れるときに。

## 5. テンポ・短縮・動きを減らす（相談 §7-5）

提案〔判断〕:
- 開く: 0.3〜0.36 秒。閉じる: **開くより短く**（0.2 秒ほど、または逆再生を速く）。毎回開くので、閉じるほうは待たせない。
- 設定に「端末の演出」: **あり／短い／なし**。なし＝0.1 秒の切り替え。今の設定の画面（Unity。`GameSettings`）に1行足せる【観察】。
- 「動きを減らす」設定（ブラウザ・OS）や、設定で「なし」のときは、拡大せず短い切り替えだけ。

## 6. 枠が消えるときの比率・文字（相談 §7-6）

- 【観察】内窓と画面が同じ比率なので、③＋寄りは**拡大1つで最後に枠なしホームとぴったり重なる**。ホームを縮めたまま使ったり、歪ませたりしない。
- 〔技術〕途中の絵は「最後のホーム（844×390）を1枚の入れ物として縮小しておき、そこから 1.0 まで拡大」にする。途中で並べ方（文字の折り返しなど）を変えない。こうすると、途中と最後で文字が飛ばない。
- 〔技術〕端末の枠の画像は 1799×874。画面いっぱいまで寄ると枠は約 1.36 倍に拡大されて外に出るので、画面に見えている間に粗さが出ないかだけ実物で確かめる【未確認】。

## 7. スマホ・WebGL の重さ（相談 §7-7）

- 【観察】再レビューの実測で、ホームの最初の読み込みは約17MB（アイコン 1254px など）。**開いた瞬間に読み込むと引っかかる**ので、探索に入ったときに先に読んでおく（または表示用の小さい画像にしておく）。偽のロード待ちは要らない。
- 【推測】拡大と暗さだけの動きは軽い（移動と透明度だけ）。重いのは「開く瞬間の画像の読み込み」と「太陽盤の炎」。
- 【未確認】実機（iPhone・Android）の滑らかさ。

## 8. 原作者に決めてほしいこと

1. 演出は **③＋寄り（推奨）**／修正版（枠を薄く）／①（構えて寄る）のどれか。迷うなら、メニュー担当に HTML で3つ並べて動く試作を作ってもらってくらべる。
2. 開く入口: 右下の端末ボタン1つ＋Esc でよいか。マークと文字。
3. 開ける場面: 自由に歩いている時だけ、でよいか（戦闘中は別に決める）。
4. 端末を取り出す SD の絵を、あとで足すか。
5. 設定に「端末の演出 あり／短い／なし」を付けるか。

## 10. 原作者の答え（2026-11-06）

1. 演出: メニュー担当に **HTML の試作を作ってもらい、③＋寄り・修正版・① をくらべる**（選ぶのは試作を見てから）。
2. 入口: 右下の端末ボタン＋Esc は、**ブラウザで遊ぶ間はそれでよい**。ただし**スマホで遊ぶときのことも考えておく**（下の「スマホの入口」）。
3. 開ける場面: **イベントの場面（シナリオの場面・支援会話など）は開けない。それ以外は開ける**。→ 総合担当の読み: プレイヤーが自分で操作できる時（探索で歩いている時、戦闘の自分の番で操作を待っている時など）は開ける。会話・演出・敵の番の動きの途中は開けない。戦闘のどの時点で開けるかの細かい所は、戦闘の画面を作るときにもう一度確かめる。
4. 端末を取り出すモーションは、SD には**つけない**。
5. 設定の「端末の演出 あり／短い／なし」は**付ける**（演出を飛ばしたい時のため）。

### 歩き方について（原作者の質問 2026-11-06）

- 【観察】Unity の 2D 探索には、**もう「押した所へ歩く」がある**。画面のどこかを押すとそこまで歩き、人を押すと隣まで歩いて話す、調べる所・出口を押すとそこまで歩いて調べる・出る。◀ ▶ は「押している間歩く」補助で、どちらも使える。
- ◀ ▶ を残すか（押した所へ歩くだけにするか）は、スマホで試してから決めればよい〔判断〕。

### スマホの入口（2 への補足。総合担当の案）

- 押した所へ歩くので、**画面のほとんどが「歩く場所」**になる。端末ボタンはその上に重ねて置き、ボタンを押しても歩かないようにする（今の Unity の作りでも、ボタンは歩く場所より手前にある【観察】）。
- 置き場所は**右下**のまま: 横持ちの右手の親指が届く。下の真ん中は「調べる・出る」の札【観察】、左右の真ん中は ◀ ▶ なので重ならない。
- 大きさは指で押しやすい **44px 以上**（画面の上の実寸。844×390 の基準でも縮んだときに下回らないように）。
- スマホの画面の端（角の丸み・カメラの切り欠き）にかからないよう、端から少し離す。
- 押した所へ歩いている途中に端末を開いたら、歩くのを止める（§4 の「押している記録を消す」と同じ）。
