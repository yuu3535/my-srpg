# 拠点メニュー Hub2 試作への総合担当の意見と原作者の答え

## 1. 確かめた範囲

- 静的サーバーで試作を開き、切り裂きの閉じる・開くが最後まで動くこと、コマ送り（開く60%）で裂け目からメニューが見えることを確認。
- `node verify-hub2-sweep.cjs` は成功。試作のページにエラーなし。
- ブラウザの表示枠が小さく、細かい見た目（1pxの線・文字の読みやすさ）は確かめていない。スマホの実機も未確認。

## 2. 意見

1. **開閉の長さ**: 閉じる1.43秒・開く1.93秒で、その間は入力を受け付けない。往復約3.4秒。メニューは何度も開くので重く感じるおそれがある。演出は残して、次の案を出した。
   - A. 演出中に押したら最後まで飛ばす
   - B. 長い演出は初回・物語の節目だけ。普段は短い版
   - C. 「短い」を初期設定にする
2. **Unity での作り**: 太陽盤は Unity に無く（ブラウザの試作だけ）、作り直しになる。裂け目のマスクは作れるが手間がかかる。背景のぼかしは WebGL では省く（正本 §3-1 で省略可）。
3. **フォントの使用条件**: ローカルフォント（ベストテン-CRT・源界明朝・Neko_no_Mezame）を、ゲームに入れて公開してよいかの記録が見つからない。WebGL ではフォントも一緒に配るので、Unity に入れる前に確かめる。
4. **担当**: 正本はCodexのメニュー案を旧案としている。
5. **シナリオで文字を変える案**: 賛成。おすすめも案と同じ（列を3つ足す／メインイベントが無い時期は枠を出さない／表に書くのは原作者、取り込みと Unity は総合担当）。場所名・章のシートを足すのは原作者。
6. **ブランチ**: `menu-motion/hub2-sweep` は試作と文書だけで、main とぶつからない。

## 3. 原作者の答え（2026-11-09）

1. 開閉の長さ: **組み合わせでよい** → **A＋B** で進める。
   - 演出中に押せば最後まで飛ばせる（入力を受け付けないのは、飛ばす操作以外）。
   - 長い切り裂きは、その日の最初の1回や物語の節目だけ。普段は短い版。
   - 設定「端末の演出：あり／短い／なし」は残す。短い版の長さ・「節目」の決め方は、メニュー演出担当と詰める。
2. 担当: 「**Codexで沼ったので（Hub2を）作った**」。拠点メニューは Hub2 の仕様書が正で、Codex のホーム（`メニューホーム_独立アプリ01/` など）は旧案。今後の Codex の担当は未定。
3. ブランチ: **main に取り込んでよい** → 2026-11-09 に main へ早送りで取り込み、プッシュ済み。
