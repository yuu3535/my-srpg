# DEVELOPMENT_REVIEW_MEMO - 自作SRPG 開発レビュー共有メモ

このメモは、Codexが現状コードと `SRPG戦闘システム_ClaudeCode用仕様整理.pdf` を読んだうえで、Claude Code側にも共有したい注意点と資産をまとめたものです。
コード変更ではなく、今後の実装判断のための作業メモです。

## まず大事にする方針

- このゲームは、昔のTRPGをSRPG化する趣味制作プロジェクト。
- 初期実装では、TRPGの自由処理を全部入れるより「まず遊べるSRPG戦闘」を安定させる。
- 基本戦闘は「陣営ターン制」「移動 + メインアクション1回」。
- 命中、回避、対抗判定はまだ確定仕様ではないため、後から差し替えやすい形を維持する。
- ビルドツールやフレームワークは導入せず、HTML/CSS/JavaScriptのブラウザ直実行構成を守る。

## これから優先してやった方が良いこと

### 1. `battleId` ごとに戦闘内容を切り替えられるようにする

`scenario.js` には `battle_tutorial` や `battle_ch1` があるが、現状の `game.js` は `playBattleScene` で `battleId` を使っていない。
そのため、章やシーンが増えても毎回同じ `CHARACTERS_DATA` 全体を使う戦闘になりやすい。

今後は以下を分けるとよい。

- 戦闘ID
- 参加ユニットID
- 敵配置
- 背景
- 勝利条件
- 敗北条件
- 先攻/後攻

これは最優先の土台整備候補。

### 2. 反撃の射程条件を仕様に合わせる

仕様PDFでは、反撃は「反撃可能な武器または行動が攻撃者に届く」ことが条件。
現状は物理反撃が距離に関係なく起きやすく、VS予測でも「反撃あり」と表示されやすい。

今後は以下を揃えるとよい。

- 実際の反撃可否
- VS予測の反撃表示
- 物理反撃と魔法反撃の射程判定
- 反撃ダメージ半減の丸め方

### 3. 状態異常ダメージ後に勝敗判定する

火傷や重力場などの継続ダメージで最後の敵/味方が倒れた時、即勝敗判定されるようにする。
現状は攻撃や魔法の後には `checkVictoryCondition()` が呼ばれるが、状態異常処理後の勝敗判定は弱い。

### 4. MP不足時の魔法ルールを決める

現状はMPが足りなくても魔法を使えて、MPが0で止まる。
SRPGとしては、次のどれにするかを決めた方がよい。

- MP不足なら使用不可
- 足りない分をHPで払う
- MP不足でも使えるが失敗/暴発リスクあり
- 特定キャラや秘伝だけ例外扱い

### 5. `magics.js` / `spells.js` / `dataHelper.js` の役割を整理する

現状の実戦闘は `spells.js` の `SPELLS_DATA` を中心に使っている。
一方で `magics.js` と `dataHelper.js` には旧形式または資料寄りのデータが残っている。

すぐ削除する必要はないが、次のどれかに決めると安全。

- `spells.js` を戦闘用の正とする
- `magics.js` は原作/TRPG資料用のマスターとして残す
- `dataHelper.js` を `spells` 対応へ更新する
- 旧形式を使わないならコメントで明記する

### 6. デバッグ用UIと本番用UIを分ける

5回タップの立ち絵調整ツールや、モードボタンから即リセットされる挙動は開発中は便利。
ただし将来的には、プレイ中に誤操作で進行が飛ぶ可能性がある。

今後は「開発モードだけ有効」などの切り替えを検討する。

## これからも資産になりそうな良いコード

### `getMoveRange` のBFS移動範囲

マス移動の土台として良い。
敵ユニットを通過不可にするなど、SRPGらしい基本が入っている。
地形コスト、飛兵、騎兵などを足す時も、この関数を拡張点にしやすい。

### `SPELLS_DATA` のデータ駆動設計

魔法を `effectType`、`range`、`mpCost`、`powerFormula` で持たせているのは良い。
仕様PDFの `Action` 構造に近く、秘伝やアイテムにも発展させやすい。

### VS予測パネル

攻撃前に命中率、期待ダメージ、反撃を見せるのはSRPGとしてかなり重要。
現状は反撃予測などにズレがあるが、UI方針としては残したい資産。

### シナリオ立ち絵レイヤー

`setCharacters` で会話中の立ち絵を切り替える仕組みは良い。
表情差分の追加にも向いている。

### 立ち絵調整ツール

5回タップで立ち絵位置を調整し、localStorageに保存できるのは制作効率が高い。
今後も残したいが、デバッグ機能として扱うと安全。

### ローディング画面

蛇、時計、金装飾のローディング演出は世界観に合っている。
このゲームの雰囲気づくりに役立つので、安易に削らない方がよい。

## 今後の実装で壊さないための注意

- `game.js` は現在、戦闘、UI、シナリオ、ホーム、調整ツールが1ファイルに集まっている。大改造は避け、機能単位で小さく触る。
- 命中/回避/反撃/状態異常は、表示と実処理がズレやすい。変更時は必ずVS予測も一緒に確認する。
- シナリオ進行と戦闘初期化は密接につながっている。`startChapter`、`playBattleScene`、`setBattleMode`、`resumeScenarioAfterBattle` は特に慎重に扱う。
- 画像パスや日本語ファイル名が多いので、素材名変更は参照箇所を検索してから行う。
- 立ち絵透過は必ず `tachie_clear.py` を使い、確定済みパラメータを勝手に変えない。
