# Declaration Patch Review

対象: `game.js` / `style.css` に残っている未コミット差分  
状態: 採用判断待ち。横画面UIプロトタイプの作業とは分離する。

## 何を追加しているか

- 味方フェーズ開始時に敵の次行動を計画する `planEnemyActions()`
- 敵行動予定を保持する `enemyDeclarations`
- 予告線、移動予定、攻撃対象マス、意図バッジを描画する `renderDeclarations()`
- 敵フェーズで予告どおりの行動を実行する `executeDeclaredAction()`
- 敵情報パネルに `予告：ATK / MOV / STN / WAIT` を表示する行
- シナリオモードでは宣言レイヤーを非表示にする処理
- 勝利/敗北時に宣言表示を消す処理

## 良い点

- 宣言制SRPGの方向性と合っている
- 敵の次行動が見えるため、位置取りの意味が増える
- スタン、移動、攻撃、待機が最低限分かれている
- 既存の敵AIを完全に消さず、宣言がある時だけ優先するため比較的安全
- 絵文字や派手な記号を使わず、UI表記は `ATK` / `MOV` / `STN` / `WAIT` に寄せている

## 注意点

- 現状の宣言AIは「一番近い味方へ近づいて攻撃」が基本で、敵アーキタイプはまだない
- 攻撃対象はユニットではなく「マス」扱いになるため、反撃予測との整合性は後で確認が必要
- 宣言線は直線なので、複数敵が増えると混線しやすい
- `DECLARATION_MODE = true` が固定値なので、テスト時に切り替えるUIや設定はまだない
- 勝利条件、防衛、離脱、ボス撃破などの新しい戦闘設計が入ると、宣言ロジックも調整が必要
- 射撃型、術師型、護衛型などを入れる前提なら、今の `planEnemyActions()` は後で分岐が増える

## 今すぐ本採用する場合の条件

- まずは「敵の次行動が見える手触り確認」と割り切る
- 敵アーキタイプや勝利条件の正式実装までは、宣言ロジックを複雑化しない
- 採用するなら専用コミットに分け、横画面UIプロトタイプとは混ぜない
- 実装後に最低限チェックすること:
  - 味方フェーズ開始時に予告が出る
  - 敵フェーズで予告が消化される
  - シナリオ画面で予告レイヤーが残らない
  - 勝利/敗北後に予告が残らない
  - 敵情報パネルに予告が表示される

## いま保留するなら

この差分は「宣言制敵行動表示の安全版試作」として保留する。  
Claude側と戦闘システム再構成の方針が決まった後、以下のどちらかを選ぶ。

1. 現差分を土台にして、敵アーキタイプ対応へ拡張する
2. 横画面UIプロトタイプ側の曲線レーザー表現に合わせて、描画部分だけ作り直す

## Codex判断

現時点では、ゲーム本体に急いで本採用するよりも、方針決定までは保留が安全。  
ただし方向性はかなり良く、宣言制を採用するなら捨てるより「試作コードとして回収する」価値が高い。
