## 2. 最初に決める開発方針

- [ ] 最初の主要対象を決める。

  - Android
  - iOS
  - Steam Deck・ゲームパッド
  - その他

## 22. 追加パッケージ候補

### 現在すぐには追加しない

- `com.unity.cinemachine`
  - マップ追従、画面揺れ、横視点戦闘カメラが必要になった段階で導入候補。
- `com.unity.addressables`
  - キャラクター、章、音声、背景が増える前に採否を決める。
- `com.unity.localization`
  - 多言語対応または文章管理の方針が決まった段階で導入候補。

### 原則不要

- `com.unity.ai.navigation`
  - マス制SRPGの移動は専用グリッド探索で扱うため、通常は不要。
- `com.unity.2d.pixel-perfect`
  - 現プロジェクトはURPであり、URP版Pixel Perfect Cameraを使うため追加しない。
- `com.unity.pipeline` 0.7.0-exp.1
  - 現在はCodexからUnity Editorを操作するために導入済み。ゲーム本体の必須機能へ依存させず、リリース前に製品ビルドへの影響と継続利用の必要性を再確認する。
- マルチプレイヤー、広告、課金、オンラインサービス関連パッケージ
  - 現在の作品目的には不要。仕様へ入った場合だけ検討する。

### パッケージ運用規則

- 必要性が確定するまで追加しない。
- Package Manager APIで互換版を解決する。
- `manifest.json`を手作業で直接変更しない。
- 追加前後にコンパイル、Play Mode、ビルドを確認する。
- PreviewまたはExperimentalパッケージを本番の必須依存にしない。

## 26. 直近で本当に必要なもの

全項目のうち、次の一歩に必要なのは以下だけ。

1. 最初の対象をWindows PC・16:9と仮定する。
2. マップ視点を仮決定する。
3. タイル寸法を仮決定する。
4. UI実験用シーンを作る。
5. 参考UIに近い案Aを仮データで組む。
6. 現行発展型の案Bと比較する。
7. アルバス魔法アニメを選択から再生までつなぐ。
8. 触ってから正式方針を決める。

この段階では、本編の全戦闘ルール、全キャラクター、全マップ、オンライン機能、Addressables、多言語、配布設定を完成させる必要はない。

## 27. 縦切り完成の判定

次を満たしたら、Unityへ本格移行するか判断できる。

- マップが表示される。
- 味方と敵が配置される。
- ユニットを選べる。
- 移動範囲が表示される。
- 移動できる。
- コマンドを選べる。
- 攻撃対象を選べる。
- 戦闘予測が表示される。
- 攻撃を実行できる。
- アルバスの魔法アニメが再生される。
- HPが変化する。
- 敵の宣言が表示される。
- キャンセルとやり直しができる。
- 一連の操作が分かりやすく、キャラクターと世界観が魅力的に見える。

この縦切りが成功した後で、ブラウザ版の全ロジック移植と本編制作へ進む。
