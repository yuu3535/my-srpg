## 追記: 魔法攻撃への反撃と、装備の射程による反撃判定（同日・Claude Code）

総合相談での決定（上の「総合相談での正式回答」5）と、原作者の指定「魔導書は魔法の扱いで射程1〜2マス、仮置きの魔導書で試してよい」を受けて実装した。ブランチ `ui/battle-reference-layout`。対象はテスト戦闘（試験用ユニット同士）。本編の旧方式の戦闘は変えていない。

### ルール（実装どおり）

- 魔法攻撃（ダメージのある魔法: `magicDamage`・`break`）も反撃の対象。命中した後に反撃の判定をする（物理攻撃と同じ）。
- 反撃できるかは、防御側が**今装備しているもの**の射程で決める。反撃のために装備を自動で持ち替えない。

- その後は従来どおり: 勇気%で反撃が起きるか → 野望で封じられないか → 速さ差5以上なら反撃の追撃。

### 画面

| 封印 | 敵1体の移動を封じる。射程は魔防÷2（CSVの字どおり。今の能力値で14〜16マス） | 命中判定あり。相手の次の番の終わりまで。**射程の読み方は原作者の確認待ち** |
| 加速 | 自分または味方1人が再行動できる。自分に使うとそのまま行動を続けられる | 回数の制限なし（MPのみ） |
| 回復 | 回復量×3 | 回復量は 6＋魔攻÷4（魔導書のたたき台の仮の式）。治癒の魔導書は×1 |

- 状態の期限の仕組みを足した: 「相手の次の番まで」の状態（封じ・虚像・封印）は、相手が自分の番を1回過ごしたあと、次の番が始まるときに消える。
- 封じ・封印を受けたユニットは移動できない（敵AIの移動先選びにも反映）。
- 戦闘予測: 落雷・万雷の補正欄に「封じ16%」のように発動率を出す。円舞・万雷は「反撃なし（範囲攻撃）」、封印・虚像は命中率と効果を出す。
- まだのもの: 転移（今は従来の自分の転移のまま。「味方を指定位置へ」の2段階の選択が必要）、召喚（幻獣のデータがない）、破壊の「魔導書に上乗せ」の扱い（今は単独の魔法のまま）。
- 確認: 全8テスト成功（battlePlan・trialStatSystem のテストを追加）。画面で全10種の動作とログ、状態の期限を確認。エラーなし。

### 転移（2段階の選択）

- 魔法コマンドで転移を選ぶと、1段階目で範囲内の味方（自分も可）が青緑に光る。味方を押すと2段階目になり、範囲内の空いているマスが光る。マスを押すと、その味方が移動する（転移を使った側は行動終了）。
- 2段階目で選んだ味方をもう一度押すと選び直し。「戻る」で取り消し。
- 範囲は CSV の「魔力÷2」を魔攻÷2 とした（アルバスで24マス。盤面ほぼ全体）。封印と同じく、射程の読み方は原作者の確認待ち。

### 原作者の回答（同日）: 封印・転移の射程

- 封印（魔防÷2）・転移（魔攻÷2）の射程は、CSVの字どおりのままでよい（正式）。
- 理由: 今のテスト戦闘のマップは仮のもので、今後はもっと広く、複雑なSRPGらしい形のマップを使う予定のため。

### 原作者の回答（同日）: 魔法戦技の扱い

- 魔法戦技は、すべて「それだけで使える魔法」（取得できるキャラが限られている魔法）。魔導書に効果を足す「上乗せ型」の案は不採用。破壊・回復なども単独の魔法として扱う（試験の実装と同じ）。
- 落雷・万雷の「魔攻÷2」は確率（魔攻÷2 %で追撃・反撃・移動の封じが発生）。試験の実装どおり。

## UIの方針決定と環状コマンド（Claude Code）

- ChatGPTのUI案と試作を比べ、方針を決めた（`docs/10-design/ui/UI_DIRECTION_AND_ASSET_LIST_2026-09-25.md` §5）。マップは画面いっぱい、コマンドはアイコンつきの環状、ユニット情報は左下、戦闘予測は頭上の小枠と決定前の大きな帯の使い分け、ステータスはタブ化。EXP・陣営・運は入れる（中身は未決定、§5.2）。
- 作業順の1番目として、戦闘画面のコマンドを**環状コマンド**に置き換えた（`game.js` の `buildLandscapeCommandRing` ほか、`style.css` の `[ring]` 節）。
  - ユニットを選ぶ → 移動先を選ぶ（この間は円環を出さない）。同じユニットをもう一度押すと、その場で円環が開く。移動した後は自動で円環が開く。
  - 魔法・戦技・持ち物・攻撃は、そのコマンドから枝のように2段目が伸びる。同じコマンドをもう一度押すか「戻る」で折りたたむ。
  - 対象を選んでいる間は円環を閉じ、画面下に「キャンセル」だけを出す（周りのマスを押せるように）。
  - コマンドのアイコンは仮のSVG。UI素材ができたら差し替える。
- 次: マップを画面いっぱいにして、UIを浮かべる形に組み替える（§5.3の2番）。

### 環状コマンドの調整（原作者の提案を採用）

- 拡大・縮小でキャラから外れる不具合を修正（円環がユニットを毎フレーム追いかける。枝も並べ直す）。
- 円環は攻撃・魔法・待機（＋持ち物）。戦技は攻撃の枝へ。詳細はユニット情報の欄を押す。取り消しは真下の × か何もないマス。
- 2段目はセフィロトの樹のような丸のツリー。戦闘予測の見出しの ‹ › で攻撃の種類を切り替えられる。
- 詳細: `docs/10-design/ui/UI_DIRECTION_AND_ASSET_LIST_2026-09-25.md` §5.1

### コマンドは右の縦並びに決定（環状コマンドは不採用）

- 環状コマンドを試作・調整したが、盤面を隠す・形が変わる・収まらないため、原作者と相談してUI案2枚目の右の縦並びに作り直した。
- 右: コマンド一覧（2段目は左隣の列）。左下: ユニットカード＋武器カード。右の縦長のユニット欄はなくした。
- 画面の更新で開いた2段目が閉じる不具合も直した（`lsOpenBranch`）。
- 詳細: `docs/10-design/ui/UI_DIRECTION_AND_ASSET_LIST_2026-09-25.md` §5.0

### 2段目の列をなくし、戦技のコマンドを戻した

- 原作者の指摘: 右の縦並びなら、戦技の枠を足して2段目の列はない方がよい。戦技・魔法の選び方は「一覧を入れ替える」を原作者が選んだ。
- 攻撃は押すとすぐ相手を選ぶ。戦技・魔法・持ち物は右の一覧がその中身に入れ替わる。予測の「戻る」は相手を選ぶ段階へ戻る。
- 詳細: `docs/10-design/ui/UI_DIRECTION_AND_ASSET_LIST_2026-09-25.md` §5.0
