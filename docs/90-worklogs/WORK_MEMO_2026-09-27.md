### 3Dの模型と、UI・イラストの調和（総合担当の考え・検討中）

- 見本の方向（盤面が主役・ダークファンタジー）とキャラのドット絵に、3Dを寄せる。やり方の候補:
  1. **模様をドット絵風に**: 模型は単純な形（ブロック・柱・幹）にして、面に貼る模様をドット絵の粗さにする（ChatGPTに真上から見た正方形の模様を頼む）。
  2. **粗い解像度で描いて拡大する**: 盤面だけを低い解像度で描き、ぼかさずに拡大する。3Dでもドット絵のキャラと同じ粗さになる。
  3. **色を絞る**: 盤面の色を、UIの黒紫・金とキャラの色から選んだ少ない色に寄せる。遠くを暗く沈める霧。
  4. **「卓上の箱庭」として見せる**: 駒の台座に立つキャラ＝原作者のTRPGの動画の表現。盤面は卓上のジオラマなので、模型らしさはむしろ合う。UIは盤面の手前に浮かぶ別の層のまま。
- T5 で 1〜3 を試して、画像で比べる。

### 隠れたキャラ（推奨）

- まず**建物・木を透けさせる**（選んだキャラ・狙う相手・カーソルのあるマスを隠している物だけ、半透明にする）。作りが簡単で、何が隠しているかも分かる。
- 輪郭を出すやり方は、描画の仕組みを足す必要がある。透けさせるやり方で足りなければ試す。

## 総合担当: マップ担当の地形の表を反映

- `Board3DLayout.cs`: 地形の配置を新しい表に（盤面の角の12マスを `t` 密な茂みに）。崩れた砦壁は (2,2) 1.3・(2,3) 1.05 で高さを変えた。木は角の茂み (0,0)(11,0)(0,6)(11,6) の模型4本（板の絵の木はやめた）。監視門 (5,0) を柱と梁の模型にして、マスの奥の辺に立て、たいまつ2本を左右の柱に付けた（通れるマスにたいまつを立てない）。橋 (6,3)(6,4) の左右の辺に欄干。道標はマスの奥の辺の近くに置いた。
- 高さ（`Board3DMap.TopHeight`）: `o` +0.3・`#` +0.5・`t` +0.6・`~` −0.18。模様は `#` が壁の上面と石積み、`t` が暗い茂み、`o` の側面が石積み。
- 移動の規則（`TerrainRules`・`MoveRange` の地形つきの計算）: 地上は `s d g =` だけ。飛行はどこでも通り抜けられ、止まれるのは `s d g = ~ o`（水堀・瓦礫の上に浮いて止まれる）。`#` `t` は通り抜けるだけ。3Dの戦闘（`Battle3DController`）もこの規則で移動範囲を出す。戦闘データに `flying`（キャラのデータにあれば）を足した。
- ブラウザ版の移動の規則には、まだ地形と飛行の区別がない（通れないマスだけ）。戦闘データに地形を入れるときに、ブラウザ版の `getMoveRange` も同じ決まりにそろえる。
- Unityのテストに地形の通行の決まり（地上・飛行の通り抜け・止まる、壁を越える、水堀の上に止まる、高さの表）を足した。

- 隠れたキャラ（推奨どおり）: 木・壁・門・高いマス（景色の崖も）が、キャラ・選んだマス・カーソルのマスを隠しているときだけ、その物を不透明度35%にする（`Board3DView.Occlusion.cs`。影も消す）。カメラやキャラが動くたびに判定する。
- 攻撃の選択肢: ブラウザ版の決め方（`landscapeForecastOptions`・`trialEnemyAttackOptions`・`getLandscapeMagicEntries`）をそのまま使い、`tools/export_unity_battle_ui.mjs` がキャラごとに書き出す（通常攻撃・物理の戦技・攻撃の魔法の戦技・魔導書の魔法、敵の選択肢、戦技と魔法の一覧）。Unity は `BattleOption` で受ける。
- 答え合わせを 272 → 448 件に増やした（全員の戦技・魔法の戦技・魔導書を、届く距離の相手へ。持ち替えも予測と同じ）。全部ブラウザ版と一致。
- コマンド: 攻撃（武器を持っているとき）・戦技・魔法（一覧に入れ替え。MPの量を出す。Unity版でまだ使えない回復・補助・範囲・召喚は「準備中」で暗く）・待機・戻る。武器を持たないアルバスには「攻撃」がない（ブラウザ版と同じ）。
- 戦闘予測: 届く攻撃が2つ以上あれば「‹ 破壊 1/2 ›」で切り替え。戦技・魔法のときはボタンが「実行する」。
- 使うときの持ち替え（ブラウザ版と同じ）: 魔導書の魔法はその魔導書に、武器の攻撃は持っている武器に持ち替える。敵は持ち替えない。
- 敵の攻撃選び: ブラウザ版と同じく、相手×動ける先×攻撃（通常攻撃・戦技・魔法。魔法はMPがあるときだけ）のすべてを評価。同じ評価なら動く距離が短いほう・通常攻撃。
- まだないもの: 回復・補助の魔法（治癒・結界・加速など）、範囲攻撃（万雷・円舞）、召喚、持ち物のコマンド（装備の持ち替え）、敵の攻撃の前の戦闘予測の表示。

## 決定: 魔法の扱い（原作者 2026-09-27）

- TRPGの魔法は、戦技・スキル・魔法武器に置き換える。素の本人の魔法は、因果Lv・兵種Lvで習得するものだけ。
- 魔法武器の呼び名を「魔核」（仮）にした（魔法は書物ではない）。表示の名前だけ変えた（火の魔核・治癒の魔核・星の魔核・仮の魔核、ユニットの詳細と身支度の「魔核・射程」）。仕組みと id は魔導書のまま。
- 最初から持っている魔核をいったん外した（リングホルム・アルシェ・カリマ・アルバス・敵アルバス）。共有の持ち物に入れたので、身支度で持たせて試せる。敵のヘレルだけ星の魔核を残した。
- 兵種Lvで習得する戦技を戦技枠に入れた（採用版 SKILL_LOADOUT_RULES どおり。これまで読み飛ばしていた）。因果の戦技のあとに並ぶ。今の試験の戦闘は兵種Lv1なので、まだ出てくるものはない（アルバスの威光は兵種Lv5）。
- 本人の戦技と魔核の魔法をどう分けるか、一族由来の魔法、魔核への適性は **検討中**: `docs/30-planning/MAGIC_CORE_DESIGN_NOTES_2026-09-27.md`。
- 注意: ブラウザ版は身支度の結果（持ち物）をブラウザに保存しているので、以前に遊んだブラウザでは古い持ち物（魔核を持ったまま）が残ることがある。
- Unity版は書き出しを作り直した（表示・攻撃の選択肢・答え合わせ 384件、全部一致）。Unity のテスト EditMode 15/15・PlayMode 3/3、ブラウザ版のテストも全部通る。

## Unity 3段目（2）: 補助の魔法・状態の時間・敵の攻撃の前の予測

- 補助の魔法（ブラウザ版 trialCastSupportArt・trialCastHeal と同じ効果）: 回復（回復量×3）・治癒の魔核（回復量＝6＋魔攻÷4）・結界（魔防÷2の装甲。次の自分の番まで）・加速（もう一度行動。自分に使えばそのまま続けて行動）。コマンド「魔法」から選び、届く味方（自分も含む。緑のマス）を押す。MPは魔法のMP（詠唱破棄の判定つき）。
- まだ「準備中」: 虚像・封印（命中の判定がある）・転移（味方と行き先の2段階で選ぶ）・範囲攻撃・召喚。
- 状態の時間（ブラウザ版 tickStatusEffects）: それぞれの番の始まりに進める。「相手の次の番まで」の状態は、相手の番を過ごしたあとに消える。火傷は1d3のダメージ。これまでUnity版では状態が消えずに残っていた（封じ・火傷など）。
- 敵の攻撃の前の予測（ブラウザ版 trialShowEnemyForecast）: 敵が動いたあと、攻撃する前に1.2秒、見るだけの戦闘予測（見出し「敵の攻撃」・ボタンなし）を出す。
- テスト: EditMode 15/15・PlayMode 4/4（補助の魔法のテストを追加）。

## Unity 3段目（3）: 虚像・封印・転移・範囲攻撃

- 虚像・封印（敵が対象）: 射程の敵（赤いマス）を押す。命中の判定（ブラウザ版 getMagicHitResult。攻撃の命中と違い、虚像の命中−20と殺気は足さない）→ MP → 効果。虚像＝命中−20、封印＝移動できない（どちらも相手の次の番まで）。命中率はブラウザ版と一致（12件）。
- 封印・封じのあいだは移動範囲が出ない（ブラウザ版 getMoveRange と同じ）。
- 転移: 1段目で範囲の味方（自分も可）、2段目で範囲の空いているマス。範囲は魔攻÷2（アルバスは25で盤面のほぼ全部。ブラウザ版の式のまま。要調整かもしれない）。
- 範囲攻撃（bpPlanArea を C# に移した）: 円舞＝隣接する敵すべてに物理攻撃、万雷＝相手の方向の直線3マスの敵すべて（直線上にない相手ならその相手だけ）。反撃・追撃なし、魔法は2人目からMPを払わない。予測は押した相手への1撃。答え合わせ48件（全部一致）。万雷はアルシェの因果Lv45なので、今の試験の戦闘ではまだ出ない。
- 敵は、これまでどおり範囲攻撃と補助の魔法を選ばない（ブラウザ版と同じ）。
- まだ「準備中」: 召喚（ヒトダマ）・専用戦技（月詠・生命吸収）。
- テスト: EditMode 16/16・PlayMode 5/5（封印・転移のテストを追加）。

## Unity: 持ち物（消耗品）（原作者 2026-09-27「消耗品をそろえる」）

- ブラウザ版の戦闘中の「持ち物」は、装備の持ち替えではなく、マップで拾った消耗品を使うコマンドだった（装備は使う技に合わせて自動で持ち替えるか、身支度で変える）。原作者の選択で、ルールは変えずにブラウザ版と同じものをUnityに入れた。

## UIの枠の縁の違和感（原作者の指摘 2026-09-27）

- 原因は素材ではなく、こちらの加工（`tools/build_ui_assets.py` の even_frame）。A1 は上辺だけ太い設計なので、上下をそろえるために下辺を反転して上に貼っていたが、貼ったのが下の28pxだけだった。四隅の飾りはそれより背が高いため、上の四隅が「下の飾り」と「上の飾り」の継ぎはぎになり、菱形の下に余分な山形と、上辺に薄い帯が出ていた。
- 直し: 下半分をまるごと反転して上半分に貼る。上の四隅と線が、下とまったく同じになった（`panel_even.png`・`panel_even_enemy.png`）。ブラウザ版（style.css の ?v=even-2）とUnity版の両方に入った。
- 原作者が四隅の小さな突起を消した A1-2（`アイコン素材/発注UI/A1-2.png`）に差し替えた（縮めると突起が潰れて見えていたため）。元の A1 は残してある。ブラウザ版 ?v=even-3・Unity版とも反映。Unity の組み立ては、中身の変わらない素材を写さないようにした（読み込み中の絵を上書きできず失敗することがあったため）。
- ユニットのカードの顔の後ろの黒い箱をやめた（原作者 2026-09-27: 黒がUIから浮いて見える）。顔の後ろは透過にして、立ち絵の右・下（と左の端を少し）を透明へ溶かす（原作者の見本の溶け方を、白ではなく透明で）。不採用: 紫の丸い光（安っぽい）、輪郭の青い光、白い背景。ブラウザ版は `.lcPortrait` の mask-image、Unity版は書き出しで端を溶かしたカード用の顔（`Art/Portraits/<id>_card.png`）。
