## 方針

- 採用するのは「枠を抜けて全画面」。端末が上がってから寄り、端末の画面がビューポートを覆うところまで拡大する
- ブラウザとスマホの両方で遊ぶ前提なので、メニューは大きく、触りやすくする
- メニューは何度も開くものなので、短くキビキビさせる。凝った起動演出は普段使いでは出さない

## 今のたたき台の課題

1. 全体が長く、一定の速さで動き続けるので重く見える
2. 端末が上がる時点で画面がもう点いているので、「端末を出す」と「メニューが開く」の区別がない
3. UIが端末と一緒に1枚の画像として動き、組み上がる感じがない
4. 背景の探索画面が反応せず、手前に重なっているだけに見える

## 開くときのタイムライン（等速、単位 ms）

| 対象 | 開始 | 長さ | 内容 | イージング |
|---|---|---|---|---|
| 背景の暗幕 | 0 | 160 | 不透明度 0 → 0.6 | ease-out |
| 背景（探索画面） | 0 | 400 | scale 1 → 1.05（少し寄る） | cubic-bezier(.16,1,.3,1) |
| 端末本体 | 0 | 380 | 下から登場：translateY(70%)・rotate(4deg)・scale(.94)・不透明度0 → 定位置（45%の時点で到着）→ 画面がビューポートを覆う倍率まで拡大 | 全体 cubic-bezier(.3,0,.2,1)、前半区間 cubic-bezier(.16,1,.3,1) |
| 端末の画面（起動） | 130 | 130 | scaleY 0.01 → 1、明るさ 3 → 1（線から点く） | cubic-bezier(.3,0,.1,1) |
| メニュー項目 | 200 + i×22 | 150 | 不透明度0・左から10px → 定位置（順番にずらして出す） | ease-out |

- 操作できるまで：約260ms
- 全体：約600ms（項目数によって変わる）

## 閉じるときのタイムライン（開くより速く）

| 対象 | 開始 | 長さ | 内容 | イージング |
|---|---|---|---|---|
| メニュー項目 | 0 | 70 | 一斉にフェードアウト | linear |
| 端末の画面 | 30 | 90 | scaleY 1 → 0.01（線になって消える） | cubic-bezier(.7,0,.9,.6) |
| 端末本体 | 90 | 150 | 現在の状態 → translateY(75%)・rotate(-3deg)・scale(.94)・不透明度0 | cubic-bezier(.5,0,.9,.4) |
| 背景の暗幕 | 90 | 150 | 0.6 → 0 | — |
| 背景（探索画面） | 90 | 200 | scale 1.05 → 1 | cubic-bezier(.16,1,.3,1) |

- 全体：約240ms

## 挙動のルール

- **入力は開き始めから受け付ける**。アニメーションが終わるまで操作できない状態は作らない
- **開いている途中で閉じる入力が来たら、その場から閉じる**。最後まで再生してから閉じる、はしない（逆も同じ）
- **寄る倍率は固定値にしない**。端末の画面部分がビューポートを覆う倍率を、ウィンドウの縦横比からその都度計算する（試作の `coverScale()`）
- **長い起動演出（スリープ画面・ロック画面からの起動など）は初回だけ**。ゲーム開始後の最初の1回やストーリーの節目にだけ出し、普段は上の短い版を使う

## 全画面にしたときの注意

- 枠が画面の外に抜けたあとも、四隅に細い金のラインや角飾りを少しだけ残して、端末の中にいる感じを保つ
- スマホのノッチ・角丸・ホームバーにかからないように、ボタン類はセーフエリアの内側に置く（抜けていく枠の装飾ははみ出してよい）
- ボタンは実寸で最低44px四方を確保する
- 横持ちだと左上の「閉じる」は親指が届きにくい。右下にも閉じる手段を置くか、背景タップや下スワイプでも閉じられるようにする

## 試作④（枠抜け全画面）へのフィードバック（2026-11-06）

「端末」ボタンと「戻る」ボタンをつけた試作④を確認。方向性はこれで確定し、あとは以下を詰める。

**良くなった点**
- 端末が上がる → 画面が線から点く → 項目が順に出る、の流れが入ってキビキビしている
- 背景が暗くなり、メニューに切り替わったことがはっきり分かる
- 「端末」「戻る」が右下にあり、横持ちの親指で押しやすい
- 閉じるときは枠を出さず、線になって消えてすぐ探索に戻る（開くより短くて正解）

**直す点**
1. **起動直後の明るいグレー画面をなくす**：画面が点いた瞬間、何も載っていない明るいグレーの板に太陽の飾りだけが乗るコマがあり、未完成の画面が見えたように感じる。線から広がる時点で、背景を最終的な暗い色にしておく
2. **出る順番と長さを詰める**：今は 太陽の飾り → 左のボタン → 上の情報 → タスク画像 → 下のアイコン の順で、揃うまで約0.9秒。全体を0.6秒以内に収める。「出撃」など触る可能性が高いものを早めに出す。太陽の飾りは画面と一緒に最初から出ていてよい
3. **閉じるときに金の線を残さない**：画面が線になったあと、その線が残ったまま探索画面が明るくなっている。線が消えてから背景を戻すか、線のフェードを早める
4. **「戻る」を「端末」ボタンとまったく同じ位置・見た目にする**：同じ場所をもう一度押せば閉じる、を体で覚えられるようにする。アイコンの並びから少し離し、機能アイコンと間違えないようにする

## 前に決まっていて、この表に入っていないこと（原作者 2026-11-06）

- 設定「端末の演出：あり／短い／なし」と「演出の速さ」（通常が初期値）。OS の動きを減らす設定のときは「なし」と同じにする。
- イベントの場面（シナリオの途中・支援会話）では開けない。それ以外では開ける。
- 入口は右下の「端末」ボタン。ブラウザでは Esc でも開け閉めする。スマホで遊ぶことも考える。
- 端末を取り出す動き（SD キャラのポーズ）はつけない。

## Unityで組む場合のメモ

- （総合担当の注記: 今の Unity のプロジェクトに DOTween は入っていない。入れるかどうかは総合担当が決める。入れない場合も、下の考え方は同じ）
- DOTween の Sequence で「端末が上がる → 画面が点く → 項目を順に出す」をつなげる想定
- 開閉の途中での切り替えに対応するため、Sequence は開く用・閉じる用を別に持ち、切り替え時に今動いている方を Kill して、現在の値から次の動きを始める
- タイミングの数値は ScriptableObject などに出しておくと、あとから調整しやすい
