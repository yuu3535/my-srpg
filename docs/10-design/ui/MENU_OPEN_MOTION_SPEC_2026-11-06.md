## 方針

- 採用するのは「枠を抜けて全画面」。端末が上がってから寄り、端末の画面がビューポートを覆うところまで拡大する
- ブラウザとスマホの両方で遊ぶ前提なので、メニューは大きく、触りやすくする
- メニューは何度も開くものなので、短くキビキビさせる。凝った起動演出は普段使いでは出さない

## 今のたたき台の課題

1. 全体が長く、一定の速さで動き続けるので重く見える
2. 端末が上がる時点で画面がもう点いているので、「端末を出す」と「メニューが開く」の区別がない
3. UIが端末と一緒に1枚の画像として動き、組み上がる感じがない
4. 背景の探索画面が反応せず、手前に重なっているだけに見える

## 「端末」と「戻る」のボタン（直し④）

- **一つのボタン**にする。閉じているときは「端末」（端末の絵）、開き始めた瞬間から同じボタンが「戻る」（左へ折り返す矢印）に変わる。閉じ始めたらまた「端末」に戻る。
- 押したときの動き: 「戻る」なら、その場から閉じる（開く途中でも）。「端末」なら、その場から開く（閉じる途中でも）。
- 置き場所: ホームのアプリ列の右に空けてある枠（`メニューホーム_独立アプリ01/home-model.js` の `returnLayout` と同じ式）。844×390 の基準で 幅44・高さ64・上端282、右端から 安全域＋4。画面上の実寸で44px四方を下回らない。アプリとの間は8px空く。
- 見た目: 絵（22px以上）の下に小さな文字（11px以上）。アルシェは金、カリマは青灰／銀の文字と縁。光らせ続けない。
- 探索の画面でも同じ位置に出るので、「同じ所をもう一度押せば閉じる」を体で覚えられる。
- 比較ページでは、ホームに空き枠だけ作ってもらい（`returnKey.enabled:true, visible:false`）、ホームの中の戻るキーは出さない。ホームのファイルは変えていない。
- 枠がとれない極小表示では、ボタンは右下の既定の位置（端から12px）に戻る。

## 挙動のルール

- **入力は開き始めから受け付ける**。アニメーションが終わるまで操作できない状態は作らない
- **開いている途中で閉じる入力が来たら、その場から閉じる**。最後まで再生してから閉じる、はしない（逆も同じ）
- **寄る倍率は固定値にしない**。端末の画面部分がビューポートを覆う倍率を、ウィンドウの縦横比からその都度計算する（試作の `coverScale()`）
- **長い起動演出（スリープ画面・ロック画面からの起動など）は初回だけ**。ゲーム開始後の最初の1回やストーリーの節目にだけ出し、普段は上の短い版を使う

## 全画面にしたときの注意

- 枠が画面の外に抜けたあとも、四隅に細い金のラインや角飾りを少しだけ残して、端末の中にいる感じを保つ
- スマホのノッチ・角丸・ホームバーにかからないように、ボタン類はセーフエリアの内側に置く（抜けていく枠の装飾ははみ出してよい）
- ボタンは実寸で最低44px四方を確保する
- 横持ちだと左上の「閉じる」は親指が届きにくい。右下にも閉じる手段を置くか、背景タップや下スワイプでも閉じられるようにする

## 試作④（枠抜け全画面）へのフィードバック（2026-11-06）

「端末」ボタンと「戻る」ボタンをつけた試作④を確認。方向性はこれで確定し、あとは以下を詰める。

**良くなった点**
- 端末が上がる → 画面が線から点く → 項目が順に出る、の流れが入ってキビキビしている
- 背景が暗くなり、メニューに切り替わったことがはっきり分かる
- 「端末」「戻る」が右下にあり、横持ちの親指で押しやすい
- 閉じるときは枠を出さず、線になって消えてすぐ探索に戻る（開くより短くて正解）

**直す点**
1. **起動直後の明るいグレー画面をなくす**：画面が点いた瞬間、何も載っていない明るいグレーの板に太陽の飾りだけが乗るコマがあり、未完成の画面が見えたように感じる。線から広がる時点で、背景を最終的な暗い色にしておく
2. **出る順番と長さを詰める**：今は 太陽の飾り → 左のボタン → 上の情報 → タスク画像 → 下のアイコン の順で、揃うまで約0.9秒。全体を0.6秒以内に収める。「出撃」など触る可能性が高いものを早めに出す。太陽の飾りは画面と一緒に最初から出ていてよい
3. **閉じるときに金の線を残さない**：画面が線になったあと、その線が残ったまま探索画面が明るくなっている。線が消えてから背景を戻すか、線のフェードを早める
4. **「戻る」を「端末」ボタンとまったく同じ位置・見た目にする**：同じ場所をもう一度押せば閉じる、を体で覚えられるようにする。アイコンの並びから少し離し、機能アイコンと間違えないようにする

**直した結果（2026-11-06 メニュー演出担当。状態：試作対象・原作者の確認待ち）**

1. 明るいグレーの板は、ホームの上に重ねていた白い光の板（不透明度0.72）だった。光は細い線のときだけにして、画面が開くにつれて消す。画面の地は最初からホームの暗い色。
2. 全体を614ms → 530msに。「出撃」を最初に、次に太陽盤の残り、下のアプリ、場所の絵（今日のタスク）、上の情報の順。太陽盤の飾りは画面と一緒に出る。
3. 閉じるとき、線を120msまでに消してから、暗幕を戻し始める（120〜240ms）。
4. 「端末」と「戻る」を一つのボタンにした（上の「「端末」と「戻る」のボタン」）。

確かめたこと: Node の検証（`verify-transition.cjs`）と、ブラウザで④をコマ送りして見た（光る線・暗い地・出る順番・閉じるときの線・ボタンの位置。アルシェ／カリマ）。確かめていないこと: 実時間でのなめらかさ（確認したときブラウザのペインが隠れていた）、スマホの実機で押したとき、遅いパソコン。

## 方向性の相談で決まったこと（原作者 2026-11-06）

- 携帯端末にする理由: アルシェとカリマは現代っ子で、タイムスリップしていることの表現。スマホは現実のプレイヤーにもなじみがあり、プレイヤーとキャラクターをつなぐ接点になる。→ メニューは「ゲームのボタンの板」ではなく「本物のスマホ」に見せる。スマホに無い物（四角い「戻る」ボタンなど）は置かない（「おもちゃみたい」に見える）。
- **開いているあいだ、端末の枠（スマホ本体のふち）は見せない**（全画面）。枠が見えるとその分画面が狭くなり、スマホで遊ぶときに操作しにくい。
- ~~閉じる操作は、ホーム画面の下の真ん中の細い横線（ホームバー）で試す~~ → **廃止**（原作者 2026-11-07）。下の「戻るボタン」へ。
  - 廃止の理由（原作者の依頼文より）: スマホのOSのジェスチャー操作とぶつかるおそれがある／戻る操作だと気づきにくい／タロット・ダークファンタジーの世界観になじまない。独自のスワイプは置かない。
- **戻るボタン（タップ）**。状態：試作対象（⑤に入れた。A・B・Cを切り替えて比べられる。第一候補はA）。探索で開く右下の「端末」ボタンは探索側のボタンとして残す（開いているあいだは出さない）。
  - 置き場所: ホームの上の段、場所の名前（〜x545）と右上の時間帯の飾り（x712〜）のあいだ。844×390基準で x650・y0・幅56・高さ44（右端706）。運命予報の帯（y44〜）にはかからない。右端から138離れているので、スマホの切り欠き（右側の safe-area）にもかからない。
  - 色: 黒・アンティークゴールド・淡いアイボリー（アルシェ）。カリマは白地に青灰の銀。太陽盤やコマンドより目立たせない。絵はすべてコードで描く（新しい画像なし）。
  - A 右上の飾りと一体（第一候補）: 「‹ 戻る」の下に細い金の線と小さな菱形。線は右へ薄れて、時間帯の飾りの横線へつながって見える。
  - B 小さなタロットカード: 黒地・二重の細い金縁のカード（26×38）、真ん中に左向きの矢印、上下に小さな点。
  - C 円い紋章: 太陽盤と同じ意匠の小さな円（半径17）。二重の金の輪と8本の短い放射、真ん中に左向きの矢印。
  - **D スリープ（月）**（原作者の案 2026-11-07。参考は原作者が別のチャットで作った試作の動画: 右の縦の列のいちばん下の月のボタンで画面が暗くなる）: 細い金の線の三日月と小さな星。右隣の時間帯の飾り（太陽）と「太陽と月」の対になる。スマホには戻るボタンはないがスリープボタンはあるので、「本物のスマホ」の方針にいちばん合う。押すと、画面の明るさが落ちるように黒い幕がかかり（100ms、2乗の ease-in）、真っ暗なあいだにしまって（30ms）、幕が引いて探索が戻る（170ms、3乗の ease-out）。全体300ms。「なし」の設定では普通にしまう。消えていく途中のEscで二重に閉じない。
  - 押したとき: 押しているあいだ少し縮む（0.94倍、80ms）→ 離すと戻る（160ms）。金の縁が一度だけ柔らかく光る（220ms、ぼかし2.5px）。粒子や強い発光はしない。
  - 連打: 押すとすぐ押せなくなり、しまい始めると140msで消える。もう一度押しても開き直したり二重にしまったりしない。Escでもしまえる。

  - ホーム内の戻るキーと、そのための空き枠は使わない（アプリの列は元の並び）。
  - 本番ではこのボタンはホームの中（Codexの受け持ち）に置くのが自然。形が決まったらCodexへの依頼文を作る。メニューの中の画面の切り替わり（めくる動き）・選んでいる項目の金の飾りが動く演出は、ボタンが決まってからの次の作業。

状態：**アイデア／試作対象**。原作者の「太陽盤を活かした、かっこよくてスタイリッシュな演出を、今までのやり方を置いて考えて」を受けた案。④の方向性（正式採用）を置き換えるものではなく、見比べて選んでもらう。試作は `メニュー開閉演出_比較01/sunfan.html`（数値は `sunfan-model.js` の `timing`）。

| メニュー項目 | 扇がその角度に届いた時 | 110 | 不透明度0・左10px → 定位置 | 3乗の ease-out |

項目の出る順番は、太陽の中心から見た角度で決まる（角度は画面の実寸から計算）。出撃 0°（177ms）→ 場所の絵 1.8° → 下のアプリ 9.7〜19.6°（右から） → 運命予報の帯 13.3° → 上の状態 16.6° → 身支度・探索 22.2° → セーブ・支援会話 42.8°（241ms）。

閉じる（通常 280ms）:

| 対象 | 開始 | 長さ | 内容 | イージング |
|---|---|---|---|---|
| メニュー項目 | 0 | 60 | 一斉に消える | linear |
| 光の扇 | 20 | 170 | 92度 → 0（たたんで針に戻る） | cubic-bezier(.55,0,.75,.2) |
| 光の針 | 170 | 60 | 太陽へ吸い込まれて消える | cubic-bezier(.6,0,.9,.5) |
| 太陽 | 150 | 130 | 回って沈む：rotate 0 → 100deg、不透明度 1 → 0、倍率 1 → 0.85 | cubic-bezier(.5,0,.9,.4) |
| 背景の暗幕 | 230 | 50 | 0.62 → 0（針が消えてから） | linear |
| 光の名残（磨き） | 0 | 50〜60 | ガラスを走る光・差しこむ光が残っていれば、すぐ消す | linear |
| 探索の画面 | 200 | 80 | scale 1.04 → 1 | cubic-bezier(.16,1,.3,1) |

- 「きらっ」（ガラスを走る光）の「初回」がいつかは総合担当が決める（案: ゲームを起動してから最初に開いたとき）。試作ページは「このページを開いてから最初の1回」で、比較用に「毎回」「出さない」も選べる。
- 「短い」は同じ動きを 開く240ms／閉じる150ms に縮める。「なし」とOSの動きを減らす設定は、切り抜き・回転なしの短いフェード（100ms／80ms）。
- 途中で反対の入力が来たら、その場の値から反対へ動く。「端末」と「戻る」は④と同じ一つのボタン、同じ位置。
- **太陽は元の素材（`太陽盤_試作03` の盤2枚・光条2枚）で、別の層として描く**。色はホームと同じ仕組み（同じフォルダの `material-engine.js`・`character-colors.js`、盤のガラス50%・光条のガラス89%）。回転・縮尺・浮かび上がりはこの層だけにかけ、メニュー画面（ホーム）は回さない。光条（針）は選んでいるコマンドの方へ回っているので、開く・閉じる瞬間にホームの中から角度を読んでそろえる。
  - 経緯（原作者指摘 2026-11-06）: 「太陽盤が出てくる瞬間途切れてる」→ 最初はホームを広がる円の窓で見せていたため、光条の先が円で切れ、暗い地が黒い円盤に見えた。次に太陽の形で切り抜いたが「すごい汚く見える。元の円盤の素材は使っちゃダメなの？」→ ホームごと回すので画面の端で太陽が斜めに切れ、形も半分の解像度でぼやけ、ガラスの奥にメニューの地が透けて濁っていた。元の素材を別の層で描く今の形にした。
  - 入れ替え: 項目が出そろったあと（380〜480ms）、ホーム自身の太陽へ入れ替える。それまでホームは「扇 − 太陽の絵の形」だけ見せ（ガラスが二重にならない）、光条のすき間にはホームの地がそのまま見える。閉じ始めは80msで動かせる太陽へ戻る。
- Unityで作るとき（総合担当への参考）: 太陽盤の絵をそのまま別の層として動かせばよい（HTML はホームを丸ごと埋め込んでいるので、入れ替えと穴あけが要っている）。扇は Image の放射状の塗り（Radial360 の fillAmount）か、回転する2枚のマスク。どちらも動かすのは大きさと回転だけで重くない。HTMLの試作だけ clip-path を使っている。ガラスを走る光は太陽のマスクの中で動かす加算の帯、差しこむ光は扇と同じマスクの中の放射グラデーションの絵（透明度だけ動かす）。
- 確かめた範囲: Node の検証（`verify-sunfan.cjs`）、ブラウザのコマ送り（アルシェ／カリマ）。実時間のなめらかさ・スマホの実機は未確認。
- 気になる点: 端末の枠を出さないので「携帯端末を開く」感じは④より弱い。カリマの明るいホームでは、扇が白い光の差しこみに見える（良し悪しは原作者の判断）。

## Unityで組む場合のメモ

- （総合担当の注記: 今の Unity のプロジェクトに DOTween は入っていない。入れるかどうかは総合担当が決める。入れない場合も、下の考え方は同じ）

- タイミングの数値は ScriptableObject などに出しておくと、あとから調整しやすい
