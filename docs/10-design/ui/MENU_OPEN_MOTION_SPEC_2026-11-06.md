## Hub2 の開閉（正。2026-11-08）

正本は `MENU_HUB2_SPEC_2026-11-08.md` の §3-12（CLOSE）・§3-14（帯スイープ）・§3-15（MENU）。ここは演出担当が読み取った要点と、今までの決まりから変わった所。数値は正本を優先する。

**帯スイープ（開く・閉じる共通）**
- 画面より大きい暗い帯（`#08070c`）が、155.2°傾いた向きで画面を横切る。全体 1.75秒。
  - 0〜46%（0〜0.805秒）: 画面の外から真ん中へ（ease-in-out）
  - 46〜54%（0.805〜0.945秒）: 画面を完全に覆って一瞬止まる
  - 54〜100%（0.945〜1.75秒）: 反対側の画面の外へ抜ける
- 帯の両端に金の光る線（3px `#f2cd78`、光彩 8/26/60px）。帯の先頭に星が乗り、長さ420pxの光の尾を引きながら1回転する。
- **閉じる**: CLOSE の星を押す → 星が弾ける（0.28秒: 1.5倍に膨らみつつ回転 → 縮んで消える）→ 帯が流れ、覆いきった瞬間（0.875秒）にメニューを消す → 探索画面に戻り、右上に MENU の星が出る。
- **開く**: MENU の星で逆向きに流し、同じ瞬間にメニューを出す。終わったら CLOSE の星が着地（1.7倍・−90°から0.5秒で弾むように戻る）。
- **演出中は入力を受け付けない**。

**CLOSE / MENU の星**
- 置き場所: 右上（基準 1688×780 で CLOSE は (1582, −2, 104, 124)、MENU は (1584, 0, 104, 124)）。CLOSE は背景なし、MENU は背景 `rgba(12,10,20,0.55)`。
- 星60px＋英字（`CLOSE` / `MENU`、12px、字間0.34em）。星は常に光彩付きで、3.4秒周期でゆっくりまたたく。ホバーで45°回転・1.12倍・光彩が強くなる。
- 「戻る」矢印やサイドキーは使わない。

## 方針（以前の④の方針。記録）

- 採用するのは「枠を抜けて全画面」。端末が上がってから寄り、端末の画面がビューポートを覆うところまで拡大する
- ブラウザとスマホの両方で遊ぶ前提なので、メニューは大きく、触りやすくする
- メニューは何度も開くものなので、短くキビキビさせる。凝った起動演出は普段使いでは出さない

## 今のたたき台の課題

1. 全体が長く、一定の速さで動き続けるので重く見える
2. 端末が上がる時点で画面がもう点いているので、「端末を出す」と「メニューが開く」の区別がない
3. UIが端末と一緒に1枚の画像として動き、組み上がる感じがない
4. 背景の探索画面が反応せず、手前に重なっているだけに見える

## 「端末」と「戻る」のボタン（直し④）

- **一つのボタン**にする。閉じているときは「端末」（端末の絵）、開き始めた瞬間から同じボタンが「戻る」（左へ折り返す矢印）に変わる。閉じ始めたらまた「端末」に戻る。
- 押したときの動き: 「戻る」なら、その場から閉じる（開く途中でも）。「端末」なら、その場から開く（閉じる途中でも）。
- 置き場所: ホームのアプリ列の右に空けてある枠（`メニューホーム_独立アプリ01/home-model.js` の `returnLayout` と同じ式）。844×390 の基準で 幅44・高さ64・上端282、右端から 安全域＋4。画面上の実寸で44px四方を下回らない。アプリとの間は8px空く。
- 見た目: 絵（22px以上）の下に小さな文字（11px以上）。アルシェは金、カリマは青灰／銀の文字と縁。光らせ続けない。
- 探索の画面でも同じ位置に出るので、「同じ所をもう一度押せば閉じる」を体で覚えられる。
- 比較ページでは、ホームに空き枠だけ作ってもらい（`returnKey.enabled:true, visible:false`）、ホームの中の戻るキーは出さない。ホームのファイルは変えていない。
- 枠がとれない極小表示では、ボタンは右下の既定の位置（端から12px）に戻る。

## 挙動のルール

- **入力は開き始めから受け付ける**。アニメーションが終わるまで操作できない状態は作らない
- **開いている途中で閉じる入力が来たら、その場から閉じる**。最後まで再生してから閉じる、はしない（逆も同じ）
- **寄る倍率は固定値にしない**。端末の画面部分がビューポートを覆う倍率を、ウィンドウの縦横比からその都度計算する（試作の `coverScale()`）

- 開閉の途中での切り替えに対応するため、Sequence は開く用・閉じる用を別に持ち、切り替え時に今動いている方を Kill して、現在の値から次の動きを始める
- タイミングの数値は ScriptableObject などに出しておくと、あとから調整しやすい
