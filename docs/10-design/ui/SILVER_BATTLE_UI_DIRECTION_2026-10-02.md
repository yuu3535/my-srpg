## 2. 原作者が求める方向性

- UIで優先するのは、ぱっと見で惹かれること、洗練・スタイリッシュさ・美しさと、見やすさ・遊びやすさ。
- 黒紫・金はオルクスの地域／世界観の色。UI全体の固定色ではない。
- 部品を矩形の箱へ分割して詰めるのではなく、盤面・人物・余白・細い意匠を画面全体として整える。
- 今回はチャコールの下地、銀の細工、明朝系の文字、控えめな青緑の強調を使った方向性。すべてのゲーム画面の最終パレットまで決定していない。
- 横画面を保ち、左右の余裕を使う。中央16:9にすべてを押し込めない。

### 通常画面

- 左上: Chapter、場所／戦場名、勝利条件。
- 左: TURNと山形の開閉操作。その下へ味方の顔一覧が伸びる。
- 閉じたときはTURNと山形だけ。「味／方」という縦ラベルにしない。
- 右上: 地形名と効果。
- 右: 人物の顔・名前・Lv・兵種・HP/MP・移動・射程・能力・武器・スキルを一目で見られる欄。

### 戦闘予測

- 右の人物欄を閉じ、下部へ攻撃側／受ける側の対戦情報を大きな帯で出す。
- 肖像は予測帯から少しだけはみ出す。情報とイラストの層を分け、すべてを枠内へ閉じ込めない。
- 名前・Lv・武器・HP前後・攻撃・命中・必殺を左右に並べ、中央に交戦の意匠。
- 下のキャンセル／攻撃する／戦闘詳細は、予測帯から離れすぎず、操作の流れが連続して見える配置。
- 予測に入ると盤面のカメラを寄せ、交戦する人物と位置関係を予測UIで隠さない。
- 一覧は予測中だけ短くし、中をスクロール。予測帯や肖像と重ならない。

### そのまま維持する／混ぜないこと

- 味方フェーズ・敵フェーズの元の切替演出を勝手に変えない。今回の見本にはフェーズ切替演出自体を入れていない。
- 移動中のゲーム画面に戦況／予測の常設ショートカットを置かない。HTML上部の「予測を試す」は見本用のツールバーであり本編HUD案ではない。
- 未制作の戦技アイコンに「破壊」の印を流用しない。
- UIと盤面を別レイヤーにすることは、UIを中央の狭い領域へ限定することではない。

## 3. 見本を開く

mainを取得したリポジトリのルートで:

```powershell
py -3.12 -m http.server 8931 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:8931/prototypes/silver-battle-ui/index.html`。

すでに8931番でサーバーが動いていれば起動し直さなくてよい。HTMLは直接開くこともできる。静的HTML/JS/CSSで、ビルドやnpmの導入は不要。

味方の選択、一覧開閉、青いマスへの移動、敵／赤いマスから予測、キャンセル、見本の攻撃、詳細、初期化を試せる。

ブラウザ確認済みの基準は1254×627、スマホ横画面の確認は844×422。2:1はこの見本の構図であり、全端末の規格決定ではない。

参照と実装の比較は `qa-comparison.html`、撮影は `qa-normal.png` と `qa-forecast.png`。QAの最終結果はpassedだが、正式UI全体の採用や本編戦闘の正しさの保証ではない。

## 4. 見本から流用してはいけないもの

- 固定のHP、能力値、命中、必殺、ダメージ、スキル効果。`model.js` は表示と状態遷移だけの仮データ。
- 移動／攻撃のマス、敵配置、障害物、カメラの固定座標。正式マップの移動可否や射程の判定ではない。
- 背景の石組み、キャラの表情・衣装・仮の魔法使い。元画像を操作可能な素材に分けるため再生成した見本素材で、正史や正式素材として未採用。
- 詳細の固定例を正式BattlePlanとして扱わない。乱数、MP、耐久、追撃・途中撃破の正式処理とは未接続。
- 本編セーブ／シナリオ／成長との接続もない。

原作者の反撃方針は変更していない。魔法も含め、装備の射程に相手が入るなら通常どおり反撃対象。射程1だけの武器で距離2の相手へ反撃は届かない。今回のHTMLはその距離判定を検証する実装ではない。

## 5. Claude Codeへのお願い（共有・調査の段階）

1. mainをpullし、上の順に読む。まず実際のHTML見本と選択元の画像を確認する。
2. この方向性を今後の戦闘UIの基準として把握し、古い色固定・中央16:9制限・汎用ブロック配置へ戻さない。

4. 今回は共有の依頼であり、ただちに本編やUnityを全面変更する依頼ではない。反映範囲・段階・影響と残る判断を原作者へ提案してから実装する。
5. 実装する場合も本編の戦闘計算を変更せず、正式な交戦計画から予測情報を受け取る。UIで独自計算を二重に持たない。
6. 元のフェーズ演出を維持し、通常／予測で交戦人物が隠れない配置とカメラを、スクリーンショットと操作で確認する。
