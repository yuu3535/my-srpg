## 1. なぜ試すのか

- 原作者の見本（`concepts/reference_battle_screen_1.jpg`・`_2.webp`、`マップ背景イメージたたき台/` の戦闘画面）は、斜め見下ろしの完成画面。
  そのため「斜めの絵（2Dの2:1アイソメトリック）を描いて敷く」作り方で始めたが、**見本の見た目**と**作り方**は別の問題だった。
- 原作者の希望（2026-09-26）: 盤面を回して、見たい角度から見たい。2Dの斜めの絵は回せない。
- 原作者の提案（2026-09-26）: まず正面（真上）の正方形のマスで綺麗に並ぶかを試し、基本ができてから斜め見下ろしにして、軸で回せるようにする。
- 3Dの盤面なら、この順番がそのまま成り立つ。真上から見れば正方形の盤面、カメラを傾ければ見本と同じ斜め見下ろし、縦の軸で回せば回転。
- 見本の城壁・床は四角い石のブロックの積み重ねで、**3Dのブロックで組む作り方と相性が良い**。高低差（城壁の上・下の通路・滝）も、2Dの1枚絵より素直に扱える。
- 参考（原作者 2026-09-26）: Unity入門の森「SRPGの作り方4 3Dマス目マップで2Dドット絵キャラを表示」
  https://feynman.co.jp/unityforest/game-create-lesson/srpg-game/2d3dmixsystem/
  3Dのブロックの盤面に、2Dのキャラの絵（Sprite Renderer）を立たせ、常にカメラの方を向かせる（ビルボード）。

## 3. 決まっていること・変わらないこと

- 横画面専用、スマホ横画面が基準。
- 論理盤面は正方形のマス。案B改のマス割り（12×8）、遮蔽物（飛行だけ通れる）、飛行は水堀・壁も越えられる。
- 画面は「背景・マップ・UI」の3段。回すなら、背景は回転に合わせて少し流すか、霧・空のような向きのない絵にする（試作で見る）。
- UIの意匠（黒紫・金の細罫線・明朝体）は変わらない。

## 4. この試作で決めたいこと（原作者）

1. マップの作り方を **3Dの盤面＋2Dのキャラ** にするか、**2Dの斜めの絵（今の作り方）** のままにするか。
2. 3Dにする場合、回し方（90°ずつ／自由に回す）と、見下ろしの角度。
3. 木・建物を、3Dの模型にするか、板に貼った絵にするか（T4の見え方で判断）。

## 5. 影響

- 3Dにした場合、Unity M1-a の表示部分（`IsoGrid`・マップの1枚絵）は作り直しになる。`MoveRange`・戦闘の計算・データの書き出しは使える。
- ChatGPTへの発注が変わる: 斜めの1枚絵ではなく、**真上から見た正方形の模様**（石畳・土・苔・水・石のブロックの側面。つなぎ目が合うもの）と、立てる物の絵になる。
- `docs/30-planning/MAP_ORDER_BORDER_WATCHROAD_2026-09-26.md`（斜めの地面マップの発注）は、この試作の結果が出るまで**保留**。

## 6. 試作の結果 T1〜T3（総合担当 2026-09-26）

状態: T1〜T3 を作った。原作者の確認待ち。T4・T5 はまだ。

### 作ったもの

- シーン: `unity-prototype/Assets/Scenes/Board3DTest.unity`（既存の `BattleM1` は変えていない）。
- 盤面: 12×8 の正方形のマス（1マス＝1×1、厚み0.3のブロック）。マスの間に少しすき間を空け、下の暗い台が目地に見える。地形は案B改の「地形の配置」の表を仮の色で。
- 向きが分かるよう、案B改の配置の位置に平たい印を置いた（青＝味方、赤＝敵、赤に黒い点＝指揮役、金に黒い点＝目的地点の監視門、白＝道標）。キャラの絵はT4。
- カメラ: 正投影。真上（T1）と斜め見下ろし（T2: 縦に30°見下ろし・横に45°）。斜めの基本の向きは、今の2Dの斜めの絵と同じ（列0・行0の角が奥）。縦に30°だと、マスは今の2Dの絵と同じ「横2：縦1」の菱形に見える。
- 回す（T3）: 90°ずつ。画面のボタン「◀ 90°」「90° ▶」、キー Q／E、横のスワイプ。回す間は0.35秒の動き。「真上から見る／斜めから見る」の切り替えも同じ動き（キー T）。
- 選ぶ: マスを押すと水色の枠が付き、左上に「列・行・地形」が出る。左下に「北」（行0＝監視門の側）の向きの矢印。
- 描画: 今のUnityの設定は2D用で3Dの陰影が出ないため、3D用の描画設定（`Assets/Settings/Renderer3D.asset`）を描画設定の一覧に足し、このシーンのカメラだけが使う。
- 組み立てと画像の書き出し: `Srpg.EditorAgent.Board3DTestBuilder.BuildAll`。マスを押して選べるかも、この中で画面上の位置から確かめている（真上で列6・行3の補修橋、斜めで列9・行2の敵）。

### 気づいたこと

- 12×8 は横長なので、90°回すと盤面の形（横長・縦長の菱形）が変わり、画面に対する大きさも変わる。今は回すたびに盤面全体が入る大きさに合わせている。実際の戦闘では、選んだキャラの近くに寄せて見るので、目立たないはず。
- 回している途中（`Board3D_T3_turning.png`）は正面から見た形になる。途中の見え方も崩れない。
- 向きの目印が盤面の中にない（仮の色の平らなマスだけ）と、回したあとに向きを見失いやすい。T4で壁・木・門が立てば、それが目印になる。北の矢印を残すかは、T4の後で決めたい。

### 原作者の感想（2026-09-26）

- Unityで触って確認できた。「戦闘準備のときにマップを見られたり、本戦闘ではいろんな角度で見られて面白い。箱庭みたいで楽しいかも」。
- 状態: **アイデア**。3Dにするかの正式決定は T4・T5 を見てから（§4）。決まったら、戦闘準備の「マップを見る」（自由に回す・寄る）と、戦闘中の回転（90°ずつ）を分けて考える。
- 直したこと: 試作の簡易ボタンの字体に日本語が入っておらず、文字が潰れていた。端末の日本語の字体（Yu Gothic UI など）を使うようにした。

## 7. 試作の結果 T4（総合担当 2026-09-26）

状態: T4 を作った。原作者の確認待ち。T5（模様）はまだ。

### 作ったもの

- キャラの盤面の絵（ブラウザ版と同じドット絵）を板にして、駒の台座（味方＝白・敵＝黒）の上に立たせた。板は常にカメラと同じ向き（どの角度から見ても正面を向く）。
  カリマは原作者が透明にした盤面の絵（`立ち絵AI生成/カリマドット絵.png`、2026-09-26）で立たせた（ブラウザ版・Unity版M1にも入れた）。
- 高さ: 水堀は低く（−0.18）、遮蔽物（瓦礫）は少し高く（+0.14）、仮の石の壁（列2・行2〜3、崩れた砦壁）は高く（1.3）。
- 仮の木を2種類: 3Dの模型（幹と葉の塊・列0・行6）と、板に貼った絵（列11・行1。仮にこちらで描いた絵）。§4 の「木・建物を3Dの模型にするか、板の絵にするか」を見比べるため。

### 確認用の画像（`unity-prototype/Assets/Previews/`）

- 4方向: `Board3D_T4_turn0.png`・`_turn90.png`・`_turn180.png`・`_turn270.png`
- 真上: `Board3D_T4_top.png`
- 寄って見る: `Board3D_T4_close_wall.png`（石の壁のまわり）、`Board3D_T4_close_tree.png`（3Dの木とリングホルム）

### 気づいたこと

- キャラの板の絵は、回しても自然に見える。ただし常に正面を向くので、回してもキャラの向き（背中など）は変わらない。向きを変えて見せるなら、キャラごとに向きの違う絵が要る（今は1枚）。
- 真上から見ると、板の絵が寝た形になり、キャラが小さく平たく見える。真上は「マップを見る」用にして、キャラは印（台座の色）で見せる方が良いかもしれない。
- 高い物の後ろのキャラ: 90° の向きで、3Dの木がリングホルムの一部を隠す。完全には隠れないが、壁や大きな木の後ろに立つと見えにくくなる。必要なら、隠れたキャラだけ輪郭を出す仕組みを足す。
- 壁は光の当たらない側が暗くなる（180° など）。回すと明るさが変わるので、光の向きをカメラに合わせて回すかは T5 で見る。
- 3Dの模型の木は、どの向きでも形が崩れない。板の絵の木は、正面から見ると絵として一番きれいだが、どの向きでも同じ形に見える（回した感じが出にくい）。

### 原作者の確認（2026-09-26〜27）

- T4 は良い。駒の台座の中にキャラが収まっている（2Dの斜めの絵の M1 ははみ出している）。
1. キャラの絵は**正面の絵だけ**で進める。向き別の絵は、作れるようになったら足す（数が多くなるので当てにしない）。
2. 真上から見たときにキャラがマスからはみ出す → **直した**。原因は台座の高さではなく、真上では板が寝るため、足元を基準にした絵が奥のマスへ伸びていたこと。真上に近づくほど、絵をマスの中央に収まる大きさ（0.86マス）へ変えるようにした。
3. 隠れたキャラ: 輪郭を出すか、建物を透けさせるか（未定。総合担当の推奨は下の通り）。
4. **光もカメラと一緒に回す** → 直した（どの向きからでも、手前の左上が明るい）。
5. 3Dの模型と、UI・イラストとの調和をどう保つか → 総合担当の考えを作業メモ（2026-09-27）に書いた。T5 で試す。

### 台座を外すか（原作者 2026-09-27 の提起・比較中）

- 原作者: 「台座はいらない可能性が高い。真上では邪魔、斜めでは台座のせいで没入感がなくなる」。
- 台座の色（味方＝白・敵＝黒）は陣営の目印も兼ねていたので、外すなら代わりが要る。3案を撮った（`Board3D_T4_foot_{Pedestal|Shadow|TeamRing}_{tilt|top}.png`）:
  - A 台座（今のもの） ／ B 台座なし・足元に丸い影だけ ／ C 台座なし・丸い影＋陣営の色の細い輪（味方＝青・敵＝赤）
- 総合担当の推奨: **C**。B だと、味方のアルバスと敵のアルバス（同じ絵）の見分けがつかない。輪は細く地面に寝ているので、キャラの絵を邪魔しにくい。
- 3Dの盤面での話。ブラウザ版・Unity版M1（2Dの斜めの絵）の台座は、決まるまでそのまま。
- **決定（原作者 2026-09-27）: 3Dの盤面では C（台座なし・足元の影＋陣営の目印）**。陣営の目印には、ゲームのUI素材を当てる。
  - 試作の既定を C にした。目印の候補を2つ撮った（`Board3D_T4_foot_TeamRing_*`・`Board3D_T4_foot_TeamFrame_*`）:
    C＝仮に描いた細い輪 ／ C'＝UI素材の盤面の枠（D4 味方・D5 敵、第2版で採用）を不透明度60%でキャラのマスに敷く。
  - C' の注意: D4・D5 は「選んでいる味方」「攻撃の相手」の枠と同じ絵なので、陣営の目印に使うなら、選んだとき・狙ったときは濃く（100%）して区別する。
- **決定（原作者 2026-09-27）: C'（UI素材の枠 D4・D5）**。試作の既定を C' にした。
  - 重なり順は **キャラ＞陣営の枠＞足元の影＞マップ**（原作者の指摘。真上で枠がキャラの絵に重なっていた）。半透明の絵の描く順（sortingOrder）で決め、キャラの足元も枠より少し上にした。
- 足の裏をマスの面にそろえた（原作者 2026-09-27）。組み立て時に絵ごとに「一番下の色のある行」（不透明度50%以上が3画素以上並ぶ行）を測り、その分だけ絵を下げる（`Board3DTestBuilder.FootFromPivot`）。測った足の下の余白: リングホルム4.4%・アルシェ6.2%・カリマ1.5%・ほか0.4〜0.6%（絵の高さに対して）。足より下に広がる魔法の光も「色」に入るので、その絵は光の下端が面に来る。絵の読み込み設定（Unity版M1と共有）は変えていない。
  - キャラの絵は今後ブラッシュアップするかもしれない（原作者 2026-09-27）。足の下の余白は組み立てのたびに測り直すので、絵を差し替えても `Board3DTestBuilder.BuildAll` を実行し直せば足の裏がそろう。

## 8. 試作の結果 T5（総合担当 2026-09-27）

状態: T5 を作った。原作者の確認待ち。

### 作ったもの

- 仮の模様（各32×32・ドット絵の粗さ・少ない色）: `tools/make_board_textures.py` が `unity-prototype/Assets/Art/Board3D/Textures/` に描く。
  - 天面: 旧石畳（白石と黒石の補修跡・目地の苔）／土道（轍・小石）／苔と下草／補修橋（継ぎ足した板・釘）／水堀（さざ波）／瓦礫／砦壁の基礎・密な下草／石の壁の上面
  - 側面: 土と石の層（マスの厚み。上端に草）／石積み（石の壁・水堀と橋の岸）
  - マスは天面と側面に別の模様を貼る箱にした。天面の模様はマスごとに90°ずつ回し、同じ模様の繰り返しを目立たなくした。3Dの木の幹と葉にも同じ模様を使った。
- 見え方を4通りで撮った（`Board3D_T5_{A|B|C|D}_{board|close}.png`）:
  - A 模様だけ ／ B 粗い解像度（1/3）で描いて、点のまま拡大 ／ C 色を寄せて遠くを霧で沈める（霧はUIの黒紫、まわりの明るさを紫寄りに、光を少し暖かく弱く） ／ D B＋C
- シーン `Board3DTest` は模様を貼った状態（A）で開く。

### 気づいたこと

- A は「卓上の箱庭」らしく、キャラのドット絵とも大きくは浮かない。
- B は、模様の点（1マス32点）が描く点より細かくなり、ざらついて見える。キャラの絵も粗くなる。B にするなら、模様を1マス16点くらいに粗くして、描く解像度と点の大きさをそろえる必要がある。
- C は全体が暗く沈み、奥が霧に溶ける。ダークファンタジーの雰囲気は出るが、奥のマスとキャラが見えにくくなるので、霧の強さは加減が要る。
- 模様は仮（ツールで描いたもの）。ChatGPTに清書を頼むなら「真上から見た正方形の模様・つなぎ目が合う・32×32（または16×16）・少ない色」。
- **決定（原作者 2026-09-27）: T5 は C（色を寄せる＋遠くを霧で沈める）**。色・明るさの方向は、原作者の原作TRPGの背景素材から読み取った方針案 `MAP_COLOR_MOOD_DIRECTION_2026-09-27.md` で作り直す（原作者の確認後）。
