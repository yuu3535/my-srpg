# マップの絵の作り方 v1（探索と戦闘で使う3Dの盤面）

作成: 2026-09-28 / 総合担当（Claude Code）
状態: **正式（作り方の標準）**。原作者の了承 2026-09-28「この作り方の文書をつくって大丈夫」。細かい値は、最初のマップ（訓練場）で試して直す
前提の文書: `UNITY_3D_BOARD_MAP_PRODUCTION_GUIDE_2026-09-27.md`（盤面の決まり）、`docs/30-planning/GROUND_IMAGE_ORDER_WATCHROAD_2026-09-27.md`（最初に試した発注）

## 0. 決まったこと

- **探索も戦闘も、同じ3Dの盤面の上で行う**（原作者 2026-09-28）。1つの場所（例: 城内廊下）は1つの盤面で、探索ではその全体を歩き、戦闘ではその中の「戦う範囲」にマス目を出して戦う。
- 地面は**真上から見た1枚絵**、高さのある物は**3Dの箱に描いた模様**か**板の絵**（国境監視路で試して、原作者が採用した方法。2026-09-27〜28）。
- 画風の基準は、国境監視路の地面のブラッシュアップ版（`マップチップ/ground_order/270a8311-….png`、原作者 2026-09-28「絵柄や色の雰囲気を優先」）。
- 絵を頼むのは ChatGPT。依頼文と下絵は総合担当が作り、原作者が渡す。

## 1. 1つの場所に頼む絵（3種類＋必要なら1種類）

| # | 絵 | 中身 | ゲームでの使い方 |
|---|---|---|---|
| ① | **床の1枚絵** | 真上から見た場所全体の床。下絵の色分けどおりに描く。高さのある物・影・マス目・文字は描かない | 盤面のすべてのマスの天面に貼る（`Board3DView.Ground`）。探索でも戦闘でも同じ絵 |
| ② | **側面・壁の模様** | その場所の壁の面・段差の側面を、正面から見た絵。左右がつながる（並べても継ぎ目が出ない）。上端・下端の縁取りつき | 壁・段差・石の基礎の3Dの箱の側面に貼る。今の仮の「土の側面」「石積み」を置き換える |
| ③ | **小物の絵をまとめた1枚** | 柱・燭台・像・旗・樽・木箱・訓練用の人形・玉座など。背景は透明（または白）、1枚に3〜6個、離して並べる | `tools/split_props.py` で1つずつに分け、キャラと同じ板の絵として立てる（木の絵と同じ） |
| ④ | 遠景（屋外だけ） | 盤面の後ろの空・森・山。向きのない絵 | 画面のいちばん奥（全体の表示で見える） |

- 屋内は天井を描かない（見下ろしなので、壁の上端で切る）。壁がキャラを隠すときは、壁を半透明にする仕組み（`Board3DView.Occlusion`）をそのまま使う。
- 同じ建物の中の場所（城内・廊下・謁見の間）は、②③を**建物ごとに共通**にしてよい（オルクス城の壁・柱は1そろい）。①だけ場所ごとに頼む。

## 2. 大きさの決まり

| 項目 | 値 |
|---|---|
| 下絵の1マス | 40px（正方形の下絵）。色の凡例を下絵の外に付けない（ChatGPT が描き込んでしまうため、凡例は依頼文に書く） |
| 1枚で頼める広さ | 最大 32×32 マス（ChatGPT の正方形の絵は約1254px なので、1マス約39px）。8:7 などの横長は作りにくいので、余白を足して正方形にし、取り込むときに切る |
| 広い場所 | 32×32 を超える場所は、**区画ごとに1枚**にする。区画の境は扉・曲がり角など、絵のつなぎ目が目立たない所にする |
| 取り込んだあと | 1マス64px（`tools/import_ground_image.py`）。元の絵は書き換えない |
| ②の模様 | 横2マス×縦1マス分（512×256 相当）。左右がつながる |
| ③の小物 | 1個が256×256くらいに収まる大きさ。足元が下の端 |

## 3. 流れ（誰が何をするか）

1. **マップ担当**（Claude の別チャット）: 場所の**配置表**を作る（§4）。物語上の意味・探索で見つかる物・戦闘の目的も書く。
2. **総合担当**: 配置表を盤面のデータにし、**下絵**（色分けの正方形）と**発注書**（§5 のひな形を埋めたもの）を作る。下絵はツールで自動で作る（§6）。
3. **原作者**: 発注書の依頼文と下絵・画風の見本を ChatGPT に渡す。届いた絵を `マップチップ/<場所の名前>/` に置く。
4. **総合担当**: 取り込んで Unity に入れ、寄り・真上・回した画像で報告する。下絵と重ねて、色の境目のずれ（マスの1/4まで）を確かめる。
5. **ゲームレビュー担当**: 点検表（`docs/40-reviews/PLAYTEST_CHECKLIST_v1.md` の A・G）で見る。
6. 原作者が採用を決める。

## 4. 配置表（マップ担当が作る）

`UNITY_3D_BOARD_MAP_PRODUCTION_GUIDE_2026-09-27.md` §3・§7 の内容に、探索のための項目を足す。

1. 場所の名前・`mapId`・列数・行数・屋内か屋外か・時間帯（昼／夕方／夜。`Board3DMood`）
2. **地形の表**（1マス1文字。記号は §7）
3. **高い物の表**（壁・柱・扉・像など。占めるマスと高さ）
4. **小物の表**（板の絵の燭台・旗など。マスの端に置く）
5. **戦う範囲**（戦闘でマス目を出す長方形。1つの場所に複数あってよい）と、敵・味方の最初の位置
6. **探索の項目**: 入口と出口（どの場所のどこへつながるか）、調べられる所、宝箱、会話の起きる所
7. **明かり**（燭台・窓・たいまつ）

## 5. 依頼文のひな形

### ① 床の1枚絵

```
添付の配置図のとおりに、ゲームのマップの「床」を、真上から見た1枚の絵として描いてください。
場所: 〈場所の名前と一言の説明（例: オルクス魔王城の訓練場。石畳の中庭で、砂を撒いた稽古場がある）〉

【絵の形】
- 真上から真下を見下ろした絵（遠近・傾きなし）。正方形。配置図と同じ位置関係で描く。
- 配置図は1マス＝40pxの格子で、色が床の種類を表しています。色の境目は、なるべく配置図どおりに（ずれてもマスの1/4まで）。
- マス目の線、文字、記号、キャラクター、UIは描かない。
- 壁・柱・扉・家具・木などの「高さのある物」は描かない（ゲーム側で立体の物を置きます）。
  そういう物が立つ所（配置図の〈色〉）は、その足元の床だけを描く。
- 強い影や、特定の方向から当たる光の筋は描かない（光と影はゲーム側で付けます）。明るさのゆるやかなムラ程度はよい。

【色の意味】
〈配置表から総合担当が書く。例: 灰色＝石の床、赤＝絨毯、砂色＝砂を撒いた稽古場…〉

【雰囲気】
〈場所の雰囲気。時間帯・古さ・手入れ・素材の色〉
- 塗りは、添付の見本の地面の絵と同じ細かさ・同じ画風の、手描き風のゲーム背景。

【大きさ】
- できるだけ大きく（正方形）。
```

### ② 側面・壁の模様

```
ゲームのマップで、3Dの箱の側面に貼る「壁の模様」を描いてください。
場所: 〈建物の名前（例: オルクス魔王城の城内）〉

- 壁を真正面から見た絵（遠近・傾きなし）。横2：縦1。
- 左右の端がつながる絵にしてください（横に何枚並べても継ぎ目が出ない）。
- 上の端に〈縁取り（例: 石の笠木）〉、下の端に〈幅木・苔など〉。
- 窓・扉・旗など、1か所だけの物は描かない（ゲーム側で別に置きます）。
- 強い影・光の筋は描かない。
- 添付の見本の地面の絵と同じ画風・同じ明るさ。
〈同じ依頼で2〜3種類: 例 ① 城内の石壁 ② 段差の側面（床より一段高い台） ③ 壊れた壁〉
```

### ③ 小物の絵

```
ゲームのマップに立てる小物を、1枚の絵にまとめて描いてください。
場所: 〈場所の名前〉

- 〈3〜6個の物の名前（例: 燭台、訓練用の木の人形、武器立て、樽、旗）〉
- 少し見下ろした正面の向き（キャラクターのドット絵と同じ向き）。
- 背景は透明（または真っ白）。物どうしは重ねず、間をあけて横に並べる。
- 影は描かない。
- 添付の見本の地面の絵・木の絵と同じ画風。
```

- 3つとも、見本として**ブラッシュアップ版の地面**と、**木の絵**（`マップチップ/ground_order/82487940-….png`）を添える。屋内の場所は、ブラウザ版の背景の絵（`背景/オルクス魔王城鍛錬場.png`・`背景/オルクス城回廊.png`・`背景/オルクス魔王城玉座の間.png`）も雰囲気の見本として添える。

## 6. ツール（総合担当）

| ツール | 今 | これから |

| 下絵を作る | **できた**: `py -3.12 tools/map_layout.py guide <配置表>` → `マップチップ/<mapId>/<mapId>_guide_square.png`（正方形・戦う範囲に赤い線）。監視路で、前の下絵とピクセルまで同じになることを確かめた | ― |
| 発注書を作る | **できた**: `py -3.12 tools/map_layout.py order <配置表>` → `マップチップ/<mapId>/<mapId>_床の発注書.md`（§5 ①の依頼文に、使っている記号の色の意味を入れる） | ― |
| ①を取り込む | **できた**: `py -3.12 tools/map_layout.py import <配置表> <届いた絵>` → `unity-prototype/Assets/Art/Board3D/Ground/<mapId>_ground.png`（余白を切り、1マス64px）。監視路で、前の取り込みと同じ絵になることを確かめた。前の `tools/import_ground_image.py` は監視路専用のまま残す | ― |
| ②を取り込む | なし | 左右のつながりを確かめ、Unity の側面の模様に入れる |
| ③を分ける | `tools/split_props.py` | そのまま使う |
| 盤面のデータ | 監視路は `Board3DLayout.cs` に直接書いている | Unity が配置表（JSON）を読み込んで盤面を作る（次の作業。高い物・小物の表の書き方もそのときに決める） |

## 7. 屋内の地形の記号（案・検討中。マップ担当が決める）

屋外の記号（`s` 石畳・`d` 土道・`g` 草・`=` 橋・`~` 水・`o` 瓦礫・`#` 石の基礎・`t` 茂み）に、屋内用を足す。

| 記号 | 地形 | 地上 | 高さ | 例 |
|---|---|---|---|---|
| `f` | 石の床 | 可 | 0 | 城内・廊下 |
| `r` | 絨毯 | 可 | 0 | 廊下の中央・謁見の間の道 |
| `a` | 砂の稽古場 | 可 | 0 | 訓練場 |
| `+` | 一段高い台 | 可 | +0.3 | 玉座の台・演台 |
| `W` | 壁 | 不可 | 1.6（見た目） | 部屋の外周 |
| `P` | 柱 | 不可 | 1.6 | 廊下・謁見の間 |
| `D` | 扉 | 可（探索では次の場所へ） | 0 | 出入口 |

- 高さが戦闘に効くか（高い台の補正）は未決定。効かないうちは、高い台を増やしすぎない（レビュー 2026-09-28 A1・A6）。

## 8. 作る順番

1. **訓練場**（オルクス魔王城の鍛錬場。プロローグの戦闘。屋外寄りで、監視路の方法に一番近い）
2. **城内廊下**（屋内の②③を初めて使う。細長いので、区画で分けるかを試す）

4. **謁見の間**（ラスボスの戦闘にも使う。玉座の台・柱・絨毯）

## 9. まだ決めていないこと

- 探索の歩き方（マスごとに進む／指で行き先を押す）と、探索中のカメラ（戦闘と同じ寄りか）。
- 場所から場所への移り方（扉で暗転して次の盤面／続けて読み込む）。
- 屋内の明るさ（城内は夜のたいまつ／昼の窓の光。`Board3DMood` に屋内用を足すか）。
- 高い台・段差の戦闘の補正。
