# Unity 3Dの盤面 戦闘マップ制作仕様

作成: 2026-09-27 / 総合担当（Claude Code）
前の版: `UNITY_ISOMETRIC_MAP_PRODUCTION_GUIDE_2026-09-26.md`（2Dの斜めの1枚絵。旧案）

## 状態

- **決定（原作者 2026-09-27）**: マップは **3Dの盤面＋2Dのキャラ** で作る。Unity版の戦闘（M1）を3Dの盤面に置き換えた。
- **総合担当の推奨どおりで進める（あとで変えられる）**: 戦闘中は45°ずつ（斜め⇔正面）＋真上、斜め見下ろしは縦30°、マスを占める高い物は3Dの模型。
- **決定（原作者 2026-09-27）: 寄りの画面を基本にする**。原作者の理想の画面（横に約10マス見える寄り・画面の端まで景色）に合わせ、盤面全体を1画面に収める「箱庭」を基本の見せ方にしない。全体はボタンで見る（戦闘準備の「マップを見る」でも使う）。**盤面の外は透明にしない**（2026-09-26 の「盤面の外は透明」は取り消し）。戦えるマスのまわりに、見た目だけの地形（景色）を置く。
  理由と比較: `MAP_BOARD_METHOD_DECISION_2026-09-27.md`
- **未決定**: 明るさ（T5 の C をもう一段明るくするか）、隠れたキャラの見せ方（半透明にする推奨）、高低差・遮蔽の戦闘補正、戦闘準備の「マップを見る」（自由に回す・寄る）。

この文書はマップのデータ・画像・Unityへの受け渡しを定める。戦闘ルールそのものは決めない。
見え方の試作の記録: `MAP_3D_BOARD_TEST_REQUEST_2026-09-26.md`（T1〜T5）。色・明るさの方針: `MAP_COLOR_MOOD_DIRECTION_2026-09-27.md`。

## 1. 基本の決まり

| 項目 | 値 |
|---|---|
| 論理盤面 | 正方形のマス（列×行）。ブラウザ版・戦闘の計算と同じ |
| 3Dでの1マス | 1×1（Unityの単位）。マスは厚み0.3のブロック、間に0.06のすき間（目地） |
| 座標の向き | 列が増えると +x（右）、行が増えると −z（手前）。盤面の中心が原点 |
| 高さ | 通常の床 0、水堀 −0.18、遮蔽物（瓦礫）+0.3、石の基礎 +0.5、密な茂み +0.6、壁 1.3（見た目の高さ。戦闘の補正にはまだ使わない）。通れない地形は、平らな暗いマスにせず高さで分かるようにする（マップ担当 2026-09-27） |
| カメラ | 正投影。斜め見下ろしは縦30°（マスが横2：縦1の菱形に見える）。基本の向きは列0・行0の角が奥 |
| 回す | 斜め見下ろしは45°ずつ（斜め⇔正面。原作者 2026-09-27）、真上は90°ずつ。回す動きは0.35秒。光もカメラと一緒に回す |
| 寄り（基本） | 理想の画面と同じくらいのマスの大きさ（正投影の縦の半分 4.0。ホイールで寄る・引く）。選んだキャラ・動く敵に寄る。指でずらして見回す（回すのはボタン）。見ている所は画面の少し上（下にUIがあるため） |
| 全体 | 盤面がまるごと入る大きさ。ボタンで切り替える |
| キャラ | 盤面のドット絵を板にして立て、常にカメラの方を向く。正面の絵だけ（向き別の絵は作れるようになったら） |
| 足元 | 台座なし。丸い影と、陣営の枠（UI素材 D4 味方・D5 敵、不透明度60%。選んだキャラは100%） |
| 重なり | キャラ＞陣営の枠＞移動範囲＞足元の影＞マップ |
| 狙われている印 | キャラのまわりの赤い丸（ゆっくり明滅） |
| 画面 | 背景・マップ・UIの3段。UIは中央の16:9の枠（`docs/10-design/ui/UI_DIRECTION_AND_ASSET_LIST_2026-09-25.md` §6） |

## 2. 重ねる層（奥から手前）

1. **背景**: 盤面の後ろの遠景（森・空・霧）。回しても違和感がないよう、**向きのない絵**にする（どの方向から見ても同じような森や霧）。画面の端から端まで。寄りの画面ではほとんど見えず、全体のときに見える
2. **景色（まわりの地形）**: 戦えるマスのまわり8マスの、見た目だけの地形。押せない・入れない（§3a）
3. **盤面**: マスのブロック（天面と側面に模様）
4. **低い飾り**: 苔・ひび・轍・血痕など。模様に描き込むか、地面に寝かせた絵
5. **足元の影・範囲・陣営の枠**（地面に寝かせた絵）
6. **キャラ**（板の絵）
7. **高い物**: 壁・門・建物・崖・橋・木（3Dの模型）。小さい物（草むら・花・旗）は板の絵
8. **明かり・演出**: たいまつ（点の光）、魔法、霧、光のにじみ
9. **UI**（16:9の枠）

## 3. マップのデータ（マップ担当が作る）

画像より先に、**地形の表**を作る。1マップにつき、次を文書に書く（今の例: `MAP_PROTOTYPE_BORDER_WATCHROAD_2026-09-26.md` §7 案B改）。

1. 列数・行数
2. **地形の表**（1マス1文字）

   | 記号 | 地形 | 地上 | 飛行: 通り抜け | 飛行: 止まる | 高さ | 天面の模様 | 側面の模様 |
   |---|---|---|---|---|---|---|---|
   | `s` | 旧石畳 | 可 | 可 | 可 | 0 | top_stone | side_earth |
   | `d` | 土道 | 可 | 可 | 可 | 0 | top_dirt | side_earth |
   | `g` | 苔と下草 | 可 | 可 | 可 | 0 | top_moss | side_earth |
   | `=` | 補修橋 | 可 | 可 | 可 | 0 | top_bridge | side_stone |
   | `~` | 水堀 | 不可 | 可 | 可 | −0.18 | top_water | side_stone |
   | `o` | 遮蔽物（瓦礫） | 不可 | 可 | 可 | +0.3 | top_rubble | side_stone |
   | `#` | 石の基礎（砦壁・監視所の跡） | 不可 | 可 | 不可 | +0.5（壁の模型が立つマスは模型の高さ） | top_wall | side_stone |
   | `t` | 密な茂み（木が立つ） | 不可 | 可 | 不可 | +0.6 | top_dark | side_earth |

   - 飛行の決まり（原作者 2026-09-27）: 足場がない所（水・穴・崖の下）には浮いて止まれる。高い物が立つ所（壁・茂み・建物）は通り抜けるだけ。低い物（瓦礫・柵）の上には止まれる。
   - 2026-09-27 に `#` を `#`（石の基礎）と `t`（密な茂み）に分けた。国境監視路の表: `MAP_PROTOTYPE_BORDER_WATCHROAD_2026-09-26.md` §7「3Dの盤面の地形・高い物の表」。

   新しい地形が要るときは、記号・通行・模様の名前を足して、総合担当へ知らせる。
3. **高い物の表**: 壁（高さ）・門・木・建物・崖・橋の欄干の、**占めるマス**と種類。1マスの物も、何マスもの物も、占めるマスをすべて書く
4. **印の表・小さい物の表**: 味方・敵・増援の配置、目的地点、道標など。小さい物（板の絵の道標・草むら・花・旗）は通行に影響せず、キャラと重ならないようマスの中心を避けて端に置く（マップ担当の提案 2026-09-27）
5. **明かり**: たいまつ・門の光などの位置
6. 物語上の意味・感情・勝敗条件・進軍ルート（`MAP_WORLD_AND_ART_DIRECTION_2026-09-26.md` の基準）

総合担当が、この表を盤面のデータ（`Board3DMap`）に写して組み立てる。今は国境監視路を `Board3DLayout.cs` に、戦闘の盤面を戦闘データから（`Battle3DController.BuildMap`）作っている。マップが増えたら、表をファイル（JSON など）で受け取る形にする。

## 3a. まわりの景色（原作者 2026-09-27）

寄りの画面の端まで景色で埋め、盤面が闇に浮いた島に見えないようにする。

- 戦えるマスの外、8マス分に置く（寄りの画面で盤面の端に寄っても、景色の外が見えない幅）。押せない・入れない・戦闘の計算に入らない。
- 今は総合担当が自動で作っている（`Board3DScenery.cs`）: 盤面の辺から出ている道・水堀はまっすぐ外へ続ける／すぐ外の1マスは低い下草と茂み（盤面の端のキャラを隠さない）／その外は外へ行くほど高い茂みと木、奥に岩の崖（記号 `c`）／手前は低く保つ。
- **マップ担当へ**: マップごとに景色の表（外の4マスの地形・高い物・物語上の意味。例: 監視門の奥へ続く道、崖の下の川、城壁の外の森）を作れるようにする。表があるマップは自動の景色の代わりに表を使う。書き方は §3 の地形の表と同じ（外の座標は −8〜列数+7）。
- 景色の中の高い物は、戦えるマスの端に立つキャラを隠さない高さにする。

## 4. 画像素材（ChatGPTに頼む）

| 素材 | 形 | 大きさ | 依頼文 |
|---|---|---|---|
| 盤面の模様（天面8種・側面2種＋景色の3種） | 真上から見た正方形・つなぎ目が合う・ドット絵 | 64×64（作るときは512×512で、8×8の点で描く。2026-09-27 に32×32から変更） | `docs/30-planning/MAP_UI_ASSET_ORDER_2026-09-26_v3.md` M5 |
| 高い物の模様（樹皮・葉・屋根・板・石積み） | 同上 | 同上 | 同 M5（盤面の模様のあとで） |
| 小さい物（草むら・花・旗・道標） | 板の絵・背景は透明・足元が下端の中央 | 256×256 | 同 M3 |
| 背景（遠景） | 向きのない森・霧・空。横に長い | 横2.16：縦1 | 同 M1 |

- 色・明るさは `MAP_COLOR_MOOD_DIRECTION_2026-09-27.md` に従う（明るさは中くらい、石は暖かい灰色〜赤茶、苔は青みのある深い緑、水は深い藍〜青緑）。
- **斜めの1枚絵（地面マップ）は作らない**。マス目に合わせた大きな絵は要らなくなった。
- 寄りの画面を基本にしたので、模様は1マスが画面の縦の約1/9（844×390で約40px）で見られる。原作者の理想の画面のように、石・草の描き込みを細かくする（M5の清書を64×64にした）。小さい物（M3）と、景色の木・崖の模様も増やす。
- 模様は仮のもの（`tools/make_board_textures.py` が描く）で動いている。清書は同じ名前・同じ大きさで差し替える。

## 5. 3Dの模型（総合担当が作る）

- 壁・門・建物・崖・橋・木は、箱・柱・円柱などを組み合わせた単純な形にして、上の模様を貼る（「卓上のジオラマ」の見え方）。
- 形はマップ担当の「高い物の表」に合わせ、占めるマスからはみ出さない。
- 回したとき・真上から見たときにも破綻しない形にする（どの方向にも側面がある）。

## 6. 見やすさの基準

- 844×390相当の横画面で確認する（斜め・真上・4方向）。
- マスの境目・通れるか・陣営の枠・範囲の表示を、模様や光より優先して読めるようにする。
- 盤面全体を暗く潰さない。通れる床は周りより一段明るく（`MAP_WORLD_AND_ART_DIRECTION_2026-09-26.md` §6）。
- 高い物がキャラ・カーソル・攻撃の相手を隠すときは、その物を一時的に半透明にする（推奨・これから作る）。回す・真上に切り替えるだけに頼らない。
- 重要な目的地点を、UIのかかる画面の端に固定しない。

## 7. 総合担当へ渡すもの（1マップごと）

`mapId`、列数・行数、地形の表、高い物の表（占めるマス・高さ・種類）、印の表、明かりの位置、背景の絵の指定、必要な新しい模様・部品の一覧、仮・採用の区別。
