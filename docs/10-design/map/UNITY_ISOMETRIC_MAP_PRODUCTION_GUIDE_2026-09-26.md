# Unity 2:1アイソメトリック戦闘マップ制作仕様

更新: 2026-09-26

## 状態

- **決定済み**: Unity版を主対象にする、スマホ横画面、2:1アイソメトリック、1マス128×64px。
- **現在の試作**: 12×8盤面を一枚絵で表示し、マス選択と移動が動作している。
- **制作方針**: 地面と高い地形部品を分け、ユニットを隠す物はUnity側で前後関係を制御できるようにする。
- **未決定**: 高低差の戦闘補正、射線、遮蔽補正、破壊可能地形、正式なカメラ切替仕様。

この文書はマップ画像とUnityへの受け渡し仕様を定めます。戦闘ルールそのものは確定しません。

## 1. 基本座標

| 項目 | 現在値 |
|---|---:|
| 論理盤面 | 正方形グリッド |
| 表示 | 横2：縦1の菱形 |
| 1マス | 128×64px |
| M1盤面 | 12列×8行 |
| M1下絵 | 1472×880px |
| 下絵 | `assets/maps/iso_trial_12x8_guide.png` |
| 座標の向き | 列が増えると右下、行が増えると左下 |
| カメラ | Orthographic、スマホ横画面 |

マップの絵は、必ず下絵の菱形位置に合わせます。遠近感を理由に奥のマスを小さくしたり、菱形を歪めたりしません。

## 2. 現在の実装事実

- `IsoGrid` が論理マスと画面位置を変換する。
- マップ本体は現在、1枚のSpriteとして盤面の下に敷かれる。
- ユニットと地形の前後順は、基本的に `列＋行` の値を基準にする。
- `wall` と `void` は通行不可として扱われる。
- 高さはまだ見た目だけで、移動・命中・射程へ影響しない。
- ユニットは画像そのものではなく、立っているマスを押して選択する。

このため、完成絵だけを先に作り込むと、絵と当たり判定が食い違う危険があります。先に論理マップを決め、その後に画像を合わせます。

## 3. 制作段階

### 段階1 試作

- 下絵に合わせた地面中心の一枚絵を使う。
- 高い壁、木、柱、屋根は盤面内へ描き込まない。
- 操作性、マス選択、UIとの重なり、画面縮小時の読みやすさを確認する。

### 段階2 実戦用

- 地面の一枚絵と、高い地形部品を分離する。
- 通行不可、遮蔽、目的地点、増援地点を座標データで持つ。
- 高い部品は透明PNGにし、Unity側でユニットとの前後順を制御する。
- 動く水、霧、炎、魔法陣は地面絵に焼き込まず、必要なら別エフェクトにする。

### 段階3 再利用

- 複数マップで繰り返す床、崖、壁、橋、森、屋内床をタイル・部品化する。
- 独自性の高い背景や遠景だけをマップごとの一枚絵にする。
- 自動接続タイルが必要になった時点で、RuleTile化をシステム担当へ相談する。

## 4. 推奨レイヤー

奥から手前へ、次の単位で分けます。

1. 遠景・盤面外背景
2. 地面・床・水面・崖の上面
3. 地面模様・破損・血痕・苔・轍などの低い装飾
4. 低い障害物・小石・短い柵・倒木
5. ユニットと台座
6. 木、柱、壁、門、旗、屋根などの高い部品
7. 選択枠、移動範囲、攻撃範囲、魔法・霧などの演出
8. 戦闘UI

盤面の外周を飾る建物や大樹も、ユニットを隠す可能性がある場合は地面絵と分けます。

## 5. 素材の種類

### 地面マップ

- 下絵と同じ画像サイズ。
- 盤面、盤面の厚み、盤面外の遠景を含めてよい。
- キャラクター、敵味方マーカー、文字、UIを入れない。
- 通行可能な床と通行不能な場所の境界を、縮小しても見分けられるようにする。

### 1マス部品

- 基本画像: 256×384px、透明PNG。
- 足元は128×64pxの菱形1マスに収める。
- ピボット候補は足元中央。正確な値は組み込み担当と確認する。
- 木、岩、柱、松明、木箱、墓石などを想定する。

### 複数マス部品

- 壁、橋、門、建物、崖など。
- 占有する論理座標を必ず併記する。
- 見た目の幅と通行不能マスが一致するようにする。
- 画像だけで仕様を伝えず、座標表も一緒に渡す。

### 演出素材

- 霧、炎、水流、魔法陣、崩落など。
- 地形ルールを変える演出は、開始条件、対象座標、持続ターン、消滅条件を別途定義する。
- 青、赤、緑は、それぞれ味方、敵・危険、回復・支援の意味と競合しないようにする。

## 6. 視認性の基準

- 844×390相当の横画面へ縮小して確認する。
- ユニットの足元、選択中のマス、敵の危険範囲を背景模様より優先する。
- 菱形の目地を強く描きすぎず、ゲーム側の範囲表示が上に載る余地を残す。
- 一本道は物語上の圧迫感を作る時だけ使い、通常戦闘では2本以上の有効な進軍ルートを用意する。
- 高い物で重要マスを隠さない。避けられない場合は透過・輪郭表示の対象として指定する。
- UIが左右と下部に重なるため、重要な目的地点を画面端へ固定しない。

## 7. カメラと視点

現在の標準は固定アイソメトリックです。過去に検討した真上視点と浅い斜め視点は、操作確認の知見として残します。

将来、視点切替を実装する場合でも、2Dアイソメ素材をそのまま自由回転させることはできません。次のいずれかが必要です。

- 同じ論理盤面を別の専用画像で表示する。
- 地形を3Dまたは複数方向の2.5D部品として作る。
- 真上へ切り替えず、ズームアウトした「戦術確認モード」で代用する。

当面は固定視点で操作性を完成させ、視点切替は別の比較検証にします。

## 8. マップごとに必要な仕様

各マップは最低限、次を記録します。

1. 舞台と物語上の目的
2. 感情・雰囲気
3. 勝利条件と敗北条件
4. 盤面サイズ
5. 味方・敵・増援の配置
6. 地形、障害物、高低差
7. 主な進軍ルートと戦術上の選択肢
8. 固有ギミック
9. カメラ・画面構成
10. 必要な画像・タイル・背景素材
11. Unityへ渡す座標・地形・画像データ
12. システム担当とシナリオ担当への確認事項

## 9. Unityへの受け渡し

画像と同時に、次の情報を渡します。

- `mapId`
- 列数、行数、1マスのピクセル数
- 原点位置
- 各マスの地形種別
- 通行可否と移動コスト
- 高さ番号。ルール未実装の間は視覚用と明記する
- 遮蔽対象かどうか
- 配置可能マス、増援マス、離脱地点、目的地点
- 各部品の占有座標、ピボット、描画順
- 背景、地面、部品、演出の画像パス候補

## 10. 画像制作前の確認

- 論理盤面と勝敗条件が先に決まっているか。
- 画像がきれいなだけの一本道になっていないか。
- 敵を倒す以外の選択を、地形が支えられるか。
- 原作世界のどの国、時代、視点、感情を表すマップか。
- 高い物を別素材にする必要がないか。
- 試作、仮採用、正式採用のどれかが明記されているか。
