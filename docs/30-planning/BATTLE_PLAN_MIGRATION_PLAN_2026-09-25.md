## 1. なぜ必要か

今の試験の戦闘（採用版ステータス）では、同じ1回の交戦を、別々の場所で計算している。

| 場所 | 何をしているか |
| --- | --- |
| 戦闘予測 `calculateBattlePrediction` | 命中・ダメージ・必殺・反撃・追撃を「見込み」で計算 |
| 味方の攻撃 `executeAttack`・`executeMagic` | 実際に乱数を振って計算し、HPを減らす |
| 敵の攻撃 `executeDeclaredAction`・`enemyAction` | 同上（2か所に同じような処理） |
| 反撃・追撃 `trialRunCounterPhase`・`runTrialFollowUp` など | 上の各所から呼ばれる |

このため、ルールを1つ足すと数か所を直す必要があり、直し漏れがそのまま「予測と実際のずれ」になる。これまでに見つけて直したずれ:

- 魔法攻撃に、実際はない追撃「×2」が予測に出ていた
- 魔法攻撃に、実際はない反撃が予測に出ていた
- 戦技つきの攻撃で、追撃まで戦技が乗ったように予測していた（実際は1撃目だけ）

今後、兵種スキル・2倍スキル・デュアル・状態異常などを足すほど、このずれは増える。

## 2. 目標の形

Codexの提案（CombatResolver → BattlePlan → BattleExecutor）に沿う。

```
攻撃の指示（誰が・誰に・何で）
   ↓
① 計算（純粋な処理。DOMや戦闘中のユニットに触れない）
   → BattlePlan: 1回の交戦で起きることを、起きる順に並べた一覧
      例: 攻撃 → 命中判定 → 必殺判定 → ダメージ → 祈り → 反撃できるか → 反撃 → 追撃 …
   ↓
② 予測: 同じ計算を「乱数を振らない見込みモード」で使い、画面の戦闘予測を作る
③ 実行: 同じ計算を「乱数を振るモード」で使い、BattlePlan の順に HP・ログ・演出へ反映する
```

- 予測と実行が**同じ計算**を通るので、ずれが構造的に起きなくなる。
- 計算はNodeのテストで確かめられる（今は `game.js` の中にあり、テストできない）。
- 乱数は外から渡す（固定の値を渡せば、毎回同じ結果になる）。テストで「初撃が外れて反撃が起き、追撃で倒れる」のような順番を確かめられる。

## 3. 範囲

- 対象は**試験の戦闘（採用版ステータスのユニット同士）だけ**。本編の旧方式の戦闘は変えない。
- 本編を採用版へ切り替える（総合相談で決めた段階導入）ときに、この一本化した計算をそのまま使う。
- 置き場所: 新しい純粋モジュール `battlePlan.js` を作る（提案）。
  - 既存の `combatPipeline.js` は旧方式（TRPG技能値の式）の影の比較用で、作りが旧方式に寄っている。
  - `trialStatSystem.js` の純粋な式（命中・ダメージ・必殺・追撃・反撃の可否・スキル補正）は、そのまま使う。

## 4. 手順（1段階＝1コミット。各段階のあとも普通に遊べる状態を保つ）

### 段階1: 1撃の計算を純粋モジュールへ移す（動きは変えない）

- 命中率・ダメージ・必殺率を、スキル補正（死神・王威・野望・一族・戦技）込みで計算する関数を `battlePlan.js` に作る。
- `game.js` の試験用の分岐（`getBattleHitResult`・`calculatePhysicalDamage`・`calculateMagicDamage`・必殺率）が、この関数を呼ぶだけにする。
- 確認: これまで画面で確かめた数値（リングホルム→ディラン 15×2、復讐 22+6、野望の必殺+10など）をNodeのテストにする。

### 段階2: 交戦の計画（BattlePlan）を作る

- 1回の交戦を、起きる順の一覧として作る関数を作る。
  - 初撃 → （命中したら）反撃できるか → 勇気%で反撃が起きるか → 野望で封じられないか → 反撃 → 攻撃側の追撃 → 反撃の追撃
  - 途中でどちらかが倒れたら、その先は起きない。祈り（HP1で耐える）とカウンター（ダメージを返す）もこの中に入れる。
- 乱数は外から渡す。テストで順番と、乱数を使う順番を固定して確かめる（Codexが挙げた必要テスト）。

### 段階3: 戦闘予測を計画から作る

- 戦闘予測を、段階2の計算の「見込みモード」から作る。予測の枠（攻撃・命中・必殺・反撃・戦闘後のHP）は計画の要約を表示するだけにする。
- 確認: 予測の数値と、固定乱数で実行した計画の数値が一致するテスト。

### 段階4: 実行を計画から行う

- 味方の攻撃（物理・魔導書の魔法・魔法の戦技・物理の戦技）と、敵の攻撃2経路を、「計画を作る → 順に反映する」形にする。
- 反映する側（`game.js`）は、HPの増減・ログ・ダメージ表示・待ち時間だけを受け持つ。
- 今あちこちにある試験用の処理（`runTrialFollowUp`・`trialRunCounterPhase`・`trialMagicCounter`・カウンターと祈りのフック）を、計画の中へまとめて消す。
- 確認: テスト戦闘を最後まで遊べること。画面で確かめてきた反撃の4パターン（射程外・武器で反撃・魔導書で反撃・治癒の魔導書）が同じになること。

### 段階5（あとで）: 敵の行動選びにも使う

- 敵がどの味方を狙うかを、同じ計算の見込みから選べるようにする。今回の範囲には入れない。

## 5. 気をつけること

- **見た目の変化**: 演出の順番や待ち時間は今と同じにする。変わるのは計算の置き場所だけ。
- **乱数の使い方**: 乱数を振る順番は変わることがある（結果の分布は同じ）。
- **本編**: 旧方式の戦闘の処理には触れない。段階ごとにチュートリアル戦闘も動作確認する。
- **作業量**: 段階1〜4で、今日の作業数回分。段階ごとに区切ってコミット・報告する。
