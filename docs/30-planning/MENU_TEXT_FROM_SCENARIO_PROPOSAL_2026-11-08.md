# メニューの文字をシナリオ進行で変える仕組み（案）

> 状態: **検討中**（メニュー演出担当の案 2026-11-08。原作者の確認待ち）
> きっかけ: 原作者「メインイベントの文章や場所の文字とかってシナリオ進行で変更できる仕様になっているの？」→「案を作って」
> 対象: 拠点メニュー Hub2（`docs/10-design/ui/MENU_HUB2_SPEC_2026-11-08.md` §5「データ連動するところ」）。Unity 版。ブラウザ版の本編は対象にしない。

## 1. 今どうなっているか

- 試作 `hub2-sweep.html` の文字（章・場所・メインイベント）は固定の見本。シナリオとはつながっていない。
- 仕様書 §5 には差し替える項目の一覧（章ラベル・章サブタイトル・場所名・イベント名・行き先・マップ上の目的地…）があるが、**どこから持ってくるかは決まっていない**。
- 今あるデータ:

| 項目 | 今あるデータ | 足りないもの |
|---|---|---|
| 章ラベル・サブタイトル | ブラウザ版 `scenario.js` の章の題名（例「プロローグ：百年戦争と祝賀会の朝」）。Unity のシナリオのデータには無い | Unity 側の置き場所 |
| 場所名 | シナリオの表の「背景」列（例 `オルクス城廊下`）。Unity のデータにも `location` として入っている | 画面に出す名前（例「オルクス城・回廊」）との対応 |
| メインイベント | 無い。表の「ゲーム処理」列に「目的地は訓練場。」のような文はあるが、決まった書き方ではない | 全部 |

## 2. 案の考え方

**シナリオを書くついでに、メニューの文字も決められるようにする。** 正本はシナリオの表（Googleドライブのスプレッドシート）のまま。取り込みの道具（`tools/import_scenario.py`）が読んで、Unity のデータに入れる。

- 書くのは「変わる行」だけ。次に書かれるまで、その文字が続く（毎行に書かなくていい）。
- 場所名は、プレイヤーが今いる場所から自動で決める（シナリオに書かない）。
- 章は、シナリオ1本（`prologue_1_1` など）ごとに1回だけ書く。

## 3. 項目ごとの決め方

### 3-1. メインイベント（イベント名・行き先・目的地）— シナリオの表に列を3つ足す

| 列の名前 | 書く内容 | 例 |
|---|---|---|
| メインイベント | 枠の大きい文字 | ギュンターとの演習 |
| 行き先 | ピンの横の小さい文字 | 訓練場へ向かう |
| 目的地 | 「マップで確認」で指す場所。「背景」列と同じ名前で書く | オルクス城訓練場 |

- その行が流れたときに、メニューのメインイベントが切り替わる。
- 次にメインイベントが書かれるまで、同じものを出し続ける。
- メインイベントが無い時期（自由行動など）は、メインイベント列に `なし` と書く → 枠を出さない（出し方は §5 の決めてほしいこと）。

**プロローグ1-1での例**（今のブロックの分け方で）:

| ブロック | 場面 | メインイベント | 行き先 | 目的地 |
|---|---|---|---|---|
| b01 | 自室・起床 | 朝の支度 | 部屋を出る | オルクス城廊下 |
| b05 | 魔王城・廊下（「目的地は訓練場」） | ギュンターとの演習 | 訓練場へ向かう | オルクス城訓練場 |
| b12 | チュートリアル戦闘終了 | （次の目的。原作者が決める） | | |

（b01 の文字は演出担当の仮。原作者が書く）

### 3-2. 場所名 — 「背景の名前 → 画面に出す名前」の対応表を1枚

| 背景（表の「背景」列） | 画面に出す名前 |
|---|---|
| アルシェ自室 | アルシェの自室 |
| オルクス城廊下 | オルクス城・回廊 |
| オルクス城謁見の間 | オルクス城・謁見の間 |
| オルクス城訓練場 | オルクス城・訓練場 |

- メニューを開いたとき、今いる場所の背景名からこの表を引いて出す。
- 表に無い背景は、背景の名前をそのまま出す（抜けがあっても空にならない）。取り込みのときに「表に無い背景」を一覧で知らせる。
- 置き場所の案: スプレッドシートに「場所名」シートを1枚足す。

### 3-3. 章ラベル・章サブタイトル — シナリオ1本ごとに1回

| 列 | 例 |
|---|---|
| 章ラベル（英字） | PROLOGUE / CHAPTER 1 |
| 章サブタイトル | 百年戦争と祝賀会の朝 |

- 置き場所の案: 「場所名」シートと同じように「章」シートを1枚。シナリオの id（`prologue_1_1`）ごとに1行。
- ブラウザ版 `scenario.js` の題名と食い違わないよう、そちらから写して始める。

### 3-4. ほかの §5 の項目（今回は案だけ）

- 時間帯: 同じやり方で、シナリオの表に「時間帯」列（朝／昼／夕方／夜）を足せる。
- 運命予報・支援の仲間・所持金・名声・NEW の札: シナリオではなくゲームの状態から出す。別に決める。

## 4. 仕組み（総合担当が組むところ）

1. `tools/import_scenario.py` が新しい列（メインイベント・行き先・目的地）を読み、その行のデータに `menu` として入れる。列が無い古い表でもそのまま動く。
2. ゲームは「今のメニューの文字」を1つ持っておき、`menu` のある行が流れたら書き換える。セーブにも入れる（ロードしたら戻る）。
3. メニューを開いたら、その文字と、今いる場所の名前（§3-2 の表）と、章（§3-3）を出す。
4. 検査: 取り込みで「目的地が背景の名前に無い」「場所名の表に無い背景がある」を知らせる。

## 5. 原作者に決めてほしいこと

1. メインイベントは **列を3つ足す**（おすすめ。書く場所がはっきりする）か、**「ゲーム処理」列に決まった書き方で書く**（例 `メイン：ギュンターとの演習／訓練場へ向かう／オルクス城訓練場`。列は増えないが書き間違えやすい）か。
2. メインイベントが無い時期の表示: 枠ごと出さない／「自由行動」などの決まった文字を出す。
3. 場所名・章の表を、スプレッドシートに新しいシートとして足してよいか。
4. 誰が書くか: シナリオの表への記入は原作者、取り込み・Unity は総合担当、でよいか。

## 6. 注意

- シナリオの正本は Google ドライブのスプレッドシート。リポジトリの xlsx は古い写しなので、取り込む前に最新を落とす。
- 「背景」列は場所の目印として使い続ける（メニューの場所名と目的地の両方がこれを頼りにする）。名前を変えるときは対応表も直す。
