## 1. 設計思想

### 1.1 目指す見た目

- **ダークファンタジーの百年戦争**。暗く重い世界の中で、キャラクターと戦況がはっきり読めること。
- **盤面が主役、UIは細い線で添える**。盤面（マップ・キャラ・演出）は色と光で見せ、UIの枠は光沢のない細い金の線で控えめにする（原作者 2026-09-25: 光沢のある枠は安っぽく見えた）。
- **UIの手本は、ステータス一覧の意匠**（黒紫の地、細い金の罫線、金の縦線の見出し、英字の小見出し＋日本語、明朝体）。
- **スマホの横画面でひと目で分かる**。小さく表示しても形（シルエット）と色で見分けられることを優先する。

### 1.2 色の役割（全素材で固定）

| 色 | 役割 | 例 |
| --- | --- | --- |
| 黒紫〜紺（#0e0b1a〜#04060e） | 地・背景 | UIの地、夜の森 |
| 紫（ヴァイオレット） | 選択中・強調の帯 | 選んだコマンドの帯 |
| 金（#c8922a〜#d6a740） | 線・見出し・大事な数字 | UIの罫線、名前 |
| アンバー（琥珀） | 落ち着いた強調 | 「実行」ボタン |
| **青** | **味方** | 味方の足元の光・移動範囲・選択枠 |
| **赤** | **敵・危険** | 敵の足元の光・攻撃範囲・敵の選択枠 |
| **緑** | **回復・補助** | 回復魔法・補助の範囲 |

- 青・赤・緑は「味方・敵・補助」の意味で使うので、それ以外の用途（飾り）には使わない。
- 光（発光・グロー）は、**盤面の演出**（魔法、足元の光、選択枠、範囲マス）だけに使う。UIの枠には使わない。

### 1.3 技術の前提（全素材共通）

- 画面: スマホの横画面（844×390 を基準。高精細の画面では2〜3倍）。
- マップ: 斜め見下ろし（アイソメトリック）。**1マスは横128×縦64px の菱形（2:1）**。
- 書き出し: **PNG・背景は透明**（マップ絵の背景部分を除く）。**1回の依頼で1素材**。
- 大きさ: UI・アイコンは「画面に出す大きさの4倍」で作る。マップ関係は §3 の指定どおり。
- 文字を入れない（文字はゲーム側で描く）。

## 3. ChatGPT への指示書

### 3.1 毎回はじめに貼る文

```
ダークファンタジーのシミュレーションRPG（百年戦争・スマホの横画面で遊ぶ）の素材を作ってください。
添付の見本の雰囲気に合わせてください。

【共通の約束】
- 1回に1つの素材だけ作る。文字は入れない。
- 指定の大きさで作る。背景は透明のPNG（マップ絵の背景部分は除く）。
- 色の役割: 青＝味方、赤＝敵・危険、緑＝回復・補助、金＝線・大事なもの、黒紫＝地。
  青・赤・緑をただの飾りに使わない。
- 画風: 暗く落ち着いたダークファンタジー。キャラと盤面は見やすく、はっきりした輪郭で。
```

### 3.2 マップ絵

`ISO_MAP_ORDER_2026-09-26.md` の依頼文を使う（下絵の上に描く。マス目の位置と大きさを変えない）。

### 3.3 マップの部品（1マスに立つ物）

```
斜め見下ろし（アイソメトリック、床の菱形は横128×縦64px）のマップに置く「{木／岩／柱／たいまつ／壁 など}」を1つ描いてください。

- 画像の大きさ: 横256×縦384px、背景は透明。
- 物の足元（地面に接する部分）は、画像の下のほうの「横128×縦64pxの菱形」の中に収める。
  菱形の中心は、画像の横の中央、下から64pxの位置。
- 上に向かって、菱形の外にはみ出して高く描いてよい（木なら枝、壁なら上の部分）。
- 光や影を画像の外に大きく広げない。地面に落ちる影は描かない。
```

### 3.4 キャラの盤面の絵

```
斜め見下ろしのマップに立たせるキャラクター「{名前}」の全身の絵を作ってください。{見た目の説明}

- 画像の大きさ: 1024×1024px、背景は透明（白い背景にしない）。
- 足の裏が画像の下から4%くらいの位置、横の中央に来るように立たせる。頭の上は少し余白を残す。
- 体はやや右向き（斜め前）。武器や魔法の光は体のまわりに収め、画像の端で切れないように。
- 画風は添付の他のキャラの盤面の絵に合わせる（等身の低いドット絵風）。
```

### 3.5 演出（魔法・当たったとき）

```
斜め見下ろしのマップで使う「{火の魔法／雷が落ちる／回復の光 など}」の演出を作ってください。

- 形式: 黒一色の背景の動画（mp4、縦長でも横長でもよい）か、同じ大きさのコマ画像の連番。
  黒い部分はゲーム側で透明にするので、背景は完全な黒（#000000）にする。
- 長さ: 1〜2秒。最初と最後は何もない黒にして、つながって繰り返せるように。
- 色は §3.1 の色の役割に合わせる（回復なら緑、など）。
```

### 3.6 UI部品・アイコン

`UI_ASSET_ORDER_2026-09-25.md` の「共通の指定」と、各素材の指定を使う（光沢・光のにじみをつけない、細い金の線）。

## 4. Codex への指示書（レビュー）

届いた画像ごとに、次を確認して `docs/40-reviews/ART_REVIEW_YYYY-MM-DD.md` に書く。

| 確認項目 | 見るところ |
| --- | --- |
| 大きさ | 指定どおりのピクセル数か |
| 背景 | 透明になっているか（白や灰色が残っていないか）。演出は背景が完全な黒か |
| 位置合わせ | マップ絵: 下絵のマス目と重ねてずれがないか。部品・キャラ: 足元が指定の位置か |
| 色の役割 | 青・赤・緑を飾りに使っていないか。UIに光沢・光のにじみがないか |
| 画風 | 既存の素材（ステータス一覧・キャラの盤面の絵）と並べて浮いていないか |
| 読みやすさ | スマホの横画面の大きさ（縮小）で、形と色が見分けられるか |

- 結果は「採用してよい／直してほしい（理由と、ChatGPTへの直しの依頼文）／不採用」の3つで書く。
- ChatGPTへの依頼文を用意するときは、§3 の型に具体的な中身を入れて、レビュー文書に残す。
- コードは変更しない。

## 5. 受け渡しの流れ

1. 原作者が ChatGPT に依頼する（§3.1 ＋ 素材ごとの型）。
2. 届いた画像を、原作者が受け取りフォルダに置く。

4. Claude Code がゲームに組み込み、組み込んだ画面の画像で報告する。
5. 原作者が確認して採用を決める。採用したら、この文書の §2 の状態を更新する。
