## 背景

- 試験ブランチ `trial/adopted-stats` のテスト戦闘を原作者が遊び、「前よりも遊びやすくなった」という感触を得た（2026-09-24）。
- 採用する場合、画面の表示を新しいステータス体系と戦闘式に合わせる必要がある。
- 検証報告: `docs/40-reviews/TRIAL_ADOPTED_STATS_VERIFICATION_2026-09-24.md`
- Codexの実装レビュー: `docs/30-planning/SYNC_AGENDA.md` §10

## 守る前提

1. **意匠は変えない。** `1efae8f` の横画面ステータスシート（黒紫の下地・紫の帯・金の細罫線・明朝体・控えめな紋章）を基準に、中身の項目だけを入れ替える（`PROJECT_CONSTITUTION.md`「UIの意匠基準」）。
2. **横画面専用。** 縦配置へ切り替えない。
3. **画面の数値は、戦闘と同じ計算元から取る。** Codexレビュー（SYNC_AGENDA §10）の指摘どおり、`calcBattleStats` を包む試験方式では、一部の値（`raw`・`skl`・`attention` など）に旧値が残り、新旧2系統が混在する。UIは、将来の共通計算（`CombatResolver` / `BattlePlan`）が返す値を表示するだけにして、画面側で独自に計算しない。
4. **戦闘予測と実戦闘の一致。** 予測に出す回数・ダメージ・確率は、実戦闘と同じ計画から作る。

## 必要な対応

### A. ステータス画面（`renderStatusSheet`）

- [ ] 基本8ステータス（HP・力・防御・魔攻・魔防・技・速さ・魅力）を主表示にする。
- [ ] 名前の横に因果Lvを表示する。兵種と兵種Lvの表示枠を用意する（兵種導入は第2段階以降）。
- [ ] 勇気は「現在値／最大値」で表示する（反撃率と必殺率に効くのは現在値）。幸運は独立値として表示する。
- [ ] 派生値（命中・回避・必殺・必殺耐性）を新しい式で表示する。必殺耐性は魅力そのもの。
- [ ] 体格（SIZ）は回避の体格補正にだけ使うため、表示するなら補足扱いにする。
- [ ] TRAINING 修練度欄を、兵種スキル・マスタースキル・因果スキルの欄へ置き換える（修練度廃止の方針に合わせる）。
- [ ] 能力上限の表示（やりこみ用）を出すかどうかは原作者が決める。

### B. 戦闘中のユニット欄（`renderLandscapeUnitPanel` ほか）

- [ ] ラベルを採用版の名称へそろえる（魔力→魔攻、物防→防御）。
- [ ] 技・速さを表示するか、限られた枠の中で優先順位を決める（追撃判定に速さが効くため、速さは表示候補）。
- [ ] LVを因果Lvへ置き換える。

### C. 戦闘予測（`calculateBattlePrediction` / `renderLandscapeBattlePreview`）

- [ ] 追撃の「×2」を、魔法攻撃と反撃側にも表示する。
- [ ] 2倍スキル（武道・魔導・急所）の発動率を表示する（兵種スキル導入後）。
- [ ] 最大ダメージ（2倍スキル×必殺＝6倍）を表示するかを原作者が決める（WORK_MEMO §15 で未決）。
- [ ] 予測は、実戦闘と同じ交戦計画から作る（Codexの `BattlePlan` 案）。

### D. 戦闘ログ

- [ ] 「【武器9 vs 回避5】」のような旧技能値の表示を、新しい命中率の表示へ置き換える。
- [ ] 追撃・反撃の追撃・必殺・2倍スキルの発生を、プレイヤーが後から追える書き方にする。
- [ ] 試験用の `[試験]` 印は、本採用時に外す。

## まだ決まっていないこと（UIの前提になるもの）

- HP換算（案①×2／案②×1）。表示するHPの桁が変わる。
- 兵種補正・兵種スキルの導入時期（第2段階）。ステータス画面の兵種欄の中身が決まる。
- 戦闘予測に最大ダメージを出すか。
- 能力上限をプレイヤーに見せるか。
- 命中係数2.5・追撃の速さ差5の確定（第2段階の検証後）。

## ステータス画面の見本（2026-09-24 作成）

`prototypes/adopted_status_sheet_prototype.html`（Claude Code 作成、原作者の確認待ち）

- 本番の `style.css` とシートの外枠・配置をそのまま使い、中身だけを入れ替えた。
- 上の操作バーで、キャラ（テスト戦闘の6体）・因果Lv・現在の勇気・能力上限の表示・HP案を切り替えられる。
- 主な変更点:
  - 名前の横を「因果Lv」に、プロフィールの「所属」を「兵種」に変更。
  - VITAL: 勇気（現在値／最大値）・幸運・反撃率・幸運勇気の成長補正。
  - BATTLE欄を「ABILITY 能力値・戦闘値」に変更。能力値（力・魔攻・防御・魔防・技・速さ・魅力・HP）と、戦闘値（命中値・回避値・必殺値・必殺耐性・追撃ライン）を並べた。
  - 命中値＝60＋技×2.5、回避値＝速さ×2.5＋体格補正とし、「命中率＝命中値−相手の回避値」で読めるようにした。
  - TRAINING修練度欄を「CLASS 兵種スキル」に置き換えた（兵種Lv5・10・15・マスター）。
  - LOADOUTに「被追撃（速さ○以上の相手から追撃を受ける）」を追加。
- 計算式の読み方は、シートの外（下）に表示している。本番でどこに出すかは未決。
- 兵種Lv・装備・MP・戦技は仮表示。

### 試験ブランチでの反映（2026-09-24、原作者の依頼）

- テスト戦闘（試験用ユニット）のステータス画面を、見本と同じ構成にした（`game.js` の `renderTrialStatusSheet`。`renderStatusSheet` の先頭で試験用ユニットだけ分岐）。
- 兵種・兵種スキルの表示データと戦闘値の計算は `trialStatSystem.js`（`TRIAL_UNIT_CLASS`・`TRIAL_CLASS_SKILLS`・`trialDerivedValues`）に置き、見本とゲームで共通化した。補助CSSは `style.css` の `[trial]` 節。
- 戦技・パッシブ・魔法・HP・MP・勇気は、戦闘中の実際の値を表示する。能力上限は表示しない（表示の可否は未決）。LOADOUTには「状態」を加えた。
- 本編（シナリオ・チュートリアル）のステータス画面は変更していない。
- 本採用時は、Codexレビューの方針どおり、共通計算（`BattlePlan`）の値を表示する形へ移す。

## 進め方の案

1. 共通計算を `combatPipeline.js` 側へ移す作業（Codex案）と並行して、UIが参照する値の一覧（表示用データの形）を先に決める。
2. ステータス画面は、`prototypes/` に横画面の試作を作り、原作者が見た目と情報量を確認してから本実装する。
3. 戦闘予測とログは、交戦計画（`BattlePlan`）の実装に合わせて更新する。
