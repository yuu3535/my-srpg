## 1. 役割

- 携帯端末メニューの**開く・閉じる演出**（と、今後のメニュー内の画面の切り替わりの動き）を設計し、ブラウザで動く試作で確かめる。
- 「スローで見る → 数値を少し変える → また見る」をくり返して、**数値表と動きの決まり**を仕上げる。
- 仕上がった数値表と決まりを総合担当に渡す。Unity に組み込むのは総合担当（§7）。

担当の分け方（原作者 2026-11-06）:

| 担当 | 受け持つもの |
|---|---|
| メニュー演出担当（このチャット） | 開閉の演出の設計・比較ページ `メニュー開閉演出_比較01/`・仕様の文書 |

## 3. 今の状態（2026-11-06）

- 方向性は **④ 枠抜け全画面・通常速度** に決まった（原作者）。端末が下から上がる → 画面が線から点く → 項目が順に出る → 枠が画面の外へ抜けて全画面、という流れ。
- 比較ページ `メニュー開閉演出_比較01/index.html` は Codex が作った。①・③＋寄り・修正版・④の4案を並べて見られる。設定（あり／短い／なし・速さ）と、ホーム右下の「戻る」キーの試作が入っている。
- 原作者が④を見て、**直してほしい点を4つ**出している（仕様 §試作④へのフィードバック）:
  1. 画面が点いた瞬間の明るいグレーの板をなくす（最初から暗い色で点く）
  2. 出る順番と長さを詰める（今は約0.9秒 → 0.6秒以内。「出撃」など、よく押す物を先に）
  3. 閉じるときに金の線を残さない
  4. 「戻る」を「端末」ボタンとまったく同じ位置・見た目にする
- **注意**: 比較ページと Codex の記録は、2026-11-06 の時点で Git にまだ入っていない（Codex の作業中）。触り始める前に、Codex にコミットしてもらってある必要がある（原作者が Codex に頼む）。入っていなければ、触る前に原作者に知らせる。

## 4. 最初にやること

1. 上の4つの直しを、比較ページの④に入れる。
2. 直した④を、原作者にブラウザで見てもらう（通常速度と 0.25倍のスロー）。
3. 仕様の表の数値を、直したあとの数値に書き直す。

④の4番（戻るの位置・見た目）は、ホームの中（Codex の受け持ち）にも関わる。ホームの中を変える必要があれば、自分で直さずに、§5 のやり方で Codex に頼む。

## 6. 決まり

> 2026-11-08 追記（メニュー演出担当）: 原作者が「Hub2に合わせる」と決めた。拠点メニューと開閉演出は `docs/10-design/ui/MENU_HUB2_SPEC_2026-11-08.md` が正。開閉は帯スイープ1.75秒、演出中は入力を受け付けない、閉じるのは右上の CLOSE の星、入口は右上の MENU の星。下の「0.6秒以内」「途中で入力を止めない」は、Hub2 の開閉には当てはめない（以前の決まりとして残す）。

- 演出は**短くキビキビ**が基本。メニューは何度も開くので、普段の開閉は約0.6秒以内、閉じるのは開くより短く。凝った起動の演出（ロック画面から起きる、など）は初回や物語の節目だけ。（→ Hub2 では開閉1.75秒）
- **途中で入力を止めない**。開いている途中で閉じれば、その場から閉じる（逆も同じ）。（→ Hub2 では演出中は入力を受け付けない）
- 動かすのは位置・大きさ・回転・透明度だけを基本にする（重くならないように。スマホとブラウザの WebGL で遊ぶ前提）。
- 色は `PROJECT_CONSTITUTION.md`「UIの優先順位」と色の調和の決まり（`docs/10-design/ui/COLOR_HARMONY_DIRECTION_2026-10-02.md`）に従う。金はアルシェ、青灰／銀はカリマの持ち主の色。
- 横画面だけ。縦に並べ替えない。ボタンは実寸で44ピクセル四方以上。スマホのノッチ・ホームバーにかからないようにする。
- 新しいライブラリは入れない。ビルドなしでブラウザから直接開ける形を保つ。
- 案には状態を付ける（アイデア／検討中／試作対象／保留／正式採用／不採用）。採用は原作者が決める。数字の見た目の好みは、何案か並べて選んでもらう。
- 確かめたことと確かめていないことを分けて書く（Node の検証だけか、ブラウザで見たか、スマホの実機で触ったか）。
- Git: ファイル名を指定してステージする（`git add .` は使わない）。1コミット1目的。コミット・プッシュは原作者に頼まれたときだけ。原作者への返事は日本語で、手順はなるべく少なく。

## 7. 総合担当へ渡すとき

演出が決まったら、仕様の文書（`MENU_OPEN_MOTION_SPEC_2026-11-06.md`）を最新にして、次がそろっているようにする:

- 開く・閉じるそれぞれの**タイムラインの表**: 動かす物、始まる時間と長さ（ミリ秒）、何から何へ（位置・大きさ・回転・透明度）、動きの曲線（`cubic-bezier(...)` の4つの数）
- 「短い」「なし」のときの表（または通常との違い）と、速さの設定の掛け方
- 途中で反対の入力が来たときの動き、入力を受け付け始める時間、連打したとき
- 項目を出す順番（どの物が何番目か）
- 全画面にしたあとに残す飾り、safe-area の扱い
- 確かめた範囲（ブラウザ・スマホの実機・遅いパソコン）

Unity の側の作り方（道具を入れるか、数値をどこに置くか）は総合担当が決める。今の Unity のプロジェクトに DOTween は入っていない。
