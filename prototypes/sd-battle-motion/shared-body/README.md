状態: **試作対象 / 未採用**。2026-10-06更新。

「身体モーションを兵種・体型ごとに共有し、頭を差し替える」方向の最初の静止検証。以前の腕リグ試作はそのまま残す。本編とUnityの描画・データ・採用素材は変更しない。現在のAutoSprite方針を置き換えた正式決定ではない。

## 開く

既存のPoCサーバーで `http://127.0.0.1:8788/shared-body/`。
サーバーが止まっている場合は、プロジェクトルートで以下を実行する。

```powershell
py -3.12 -m http.server 8788 --bind 127.0.0.1 --directory prototypes/sd-battle-motion
```

初期表示は戦列下級・子供のA1。アルシェ／カリマの元SDから分離した頭と、衣装A1・A2・A3を並べて比較する。選択した衣装は、その下で元SDの隣表示・透かし表示と比較できる。以前の3身体系統は「以前の身体試作を開く」に残す。キャラごとの頭サイズと首合わせを調整できる。編集中の調整値は身体×キャラで保持するが、未記録の変更は再読込で初期値へ戻る。記録した外見はブラウザに残り、一覧から明示的に呼び出せる。衣装比較の作業JSONの読込にも対応。

### キャラ×汎用兵種の外見記録（2026-10-06追加）

原作者の依頼により、静止外見を記録して再利用する機能を追加。状態は引き続き**試作対象**。本編／Unityへの接続、衣装や配色の正式採用は行っていない。

画面の左は手順の順に並んでいる（2026-10-06 総合担当が整理。原作者の依頼「迷わず使えるように」）。

1. **STEP 1 キャラ・兵種・衣装を選ぶ**: キャラ、汎用兵種、衣装案A1〜A3。
2. **STEP 2 頭を合わせる**: 頭の大きさ・首合わせ・首の接合マスク。A1の配色は右の「配色」の欄。元SDとの比較・剣・ガイド・反転は「表示の補助（記録には入りません）」に畳んである。
3. **STEP 3 記録する**: 「いまの見た目を記録」。記録名は任意。同じ組み合わせを記録し直すと新しい履歴が追加され、古い内容は残る。
4. **STEP 4 記録した見た目を呼び出す**: 一覧から選んで「選んだ見た目を呼び出す」。呼び出したあと調整したら STEP 3 で記録し直す。起動時に編集中の見た目を勝手に上書きしない。
5. **JSONで保存・読込（別の操作）**: 左のいちばん下の囲み。ふだんは使わない。作業の区切り・別PC・別ブラウザ・人に渡すときに、記録一覧JSON／作業全体JSONを保存し、ファイル選択か全文の貼り付けで読み込む。ダウンロードできない環境では表示されたJSON本文をコピーする。

- 右の上の **「いま表示している見た目」** に、今の見た目の出どころを出す: 記録していない編集中／記録したばかり／一覧から呼び出した記録／JSON（ファイル名）から読み込んだ記録／作業全体JSONから戻した調整中の値。呼び出したあとに変えると「変更あり（まだ記録していません）」と出て、色が変わる。
- JSONから読み込んだ記録は STEP 4 の一覧に入り、「JSONから」の印が付く（このタブで読み込んだ物）。表示中の記録には「◀ 表示中」の印。

原作者確認の運用: **普段の微調整・キャラ切替は「記録」、JSONバックアップは作業の区切り・共有時だけ**。キャラごと・微調整ごとに別JSONをダウンロードする必要はない。一覧JSONは全記録、作業全体JSONは両キャラの編集中調整もまとめる。ブラウザ内履歴は記録のたびに増える仕様で、最新版の上書き更新／履歴整理機能は未実装。ダウンロードしたバックアップが自動的にゲームへ読み込まれることはない。

JSON外見呼出の操作改善: 「JSONから見た目を呼び出す」欄とファイル選択を常時表示。保存済みの作業全体JSONは選択中の衣装・配色・頭合わせまで即座に復元する。一覧JSONは1件ならその見た目を即表示、複数件なら読み込んだ記録のうち現在のキャラ×兵種の最新（なければ保存日時が新しい記録）を一覧で選択し、「選択した記録を呼び出す」で表示する。複数件の読込だけでは編集中の見た目を上書きしない。空の一覧も見た目を変えない。本文貼付は補助の折りたたみ欄に残す。ファイル／本文どちらも既存記録を消さずマージし、呼出時にバックアップファイルや新規履歴を自動生成しない。キャッシュ参照は `20261006-5`（2026-10-06 の整理で `20261006-6`）。`generated/json_appearance_recall_preview.png` はカリマの仮配色をJSONから呼び出した操作確認用の画面。

- 外見の識別単位は `characterId × classId × bodyType`。A1/A2/A3は別兵種ではなく、同じ兵種の衣装案。現在は本編ID `young_arshe` / `young_karima`、`戦列下級`、`child` の2組に対応。ほかの11汎用兵種は本編の `ABILITY_DATA.classLines` に合わせて表示するが、衣装未登録として選択不可。ギュンターと旧身体試作は記録対象外。

`preset-core.js` はDOM・保存先に依存しない純粋処理。将来の描画側はJSONを検証したうえで、以下のように外見を取得できる。本編はまだこのモジュールを読み込んでいない。

### 元SDとの比較（2026-10-05追加）

調整中のキャラを、左に「合成＋半透明の元SD」、右に「元SDそのまま」で並べる。キャラ選択と連動する。3人の共通身体の比較は折りたたみ欄に残している。

- 「元SDを透かして重ねる」で表示を切替。不透明度は0〜100%。
- 「重ねる元SDを単色シルエットに」で、衣装の柄に左右されず輪郭を見比べる。右の原画は単色化しない。
- 元SDの大きさは75〜125%、重ね位置は左右±120px・上下±50pxで調整。原作者依頼で左右の範囲を±60から2倍へ拡張。位置の移動は左だけ、大きさは右にも反映する。
- 初期合成の全高と、元SDの有効輪郭（alpha>=24の矩形）の全高・足元を合わせる。調整中の頭の大きさに自動追従させないので、頭サイズを変えた差が見える。輪郭矩形は座標計算にのみ使い、元画像の画素はそのまま描画する。
- 元SDの位置・大きさは身体×キャラごとに独立して保持。「元SDの大きさ・位置を戻す」は頭の調整をリセットしない。
- 比較用の調整値もJSONの `referenceAdjustments` に書き出す（version 2）。

ポーズ・服・武器の差まで一致させる機能ではない。頭・肩・腰・足元のバランスを見るための比較。元画像は変更せず、単色表示も画面描画だけで行う。

左右拡張に合わせて元SD比較キャンバスを1000×520へ広げ、元SDが端で欠けにくい余白を確保した。座標テストは従来±60に加え±120を含む675通りと反転時の範囲を検証。頭の首合わせ（±18px）とは別の操作。既存タブは自動再読込せず、必要な調整は保存してから更新する。

## 素材と生成

画像生成スキルに従い、組込み画像生成の透過PNGモードを使用。外部AutoSpriteへのアップロード・購入はしていない。プロンプトと参照用途は [PROMPTS.md](PROMPTS.md)。

身体2枚と頭3個のアトラスを生成し、アトラスの間隔・周囲のぼかし除去を再依頼した。出力は指定したアトラス幅・間隔からずれ、周辺の半透明ハローが残った。そのため既存の `tools/tachie_studio.py.process` で透過仕上げし、`prepare_assets.py` で輪郭の実際の矩形を機械的に切り出した。独自の透過処理は実装していない。

- `assets/*_source.png`: 生成原本のコピー（元キャラ画像を上書きしていない）。
- `assets/*_clear.png`: 既存Studioで仕上げた画像。
- `assets/child_body.png` / `standard_body.png`: 共通身体。
- `assets/provided_child_body.png`: 原作者が提供した子供素体の変更なしコピー。
- `assets/arshe_head.png` / `karima_head.png` / `gunter_head.png`: 合成用の頭。
- `assets/*_original.png`: 比較用の既存SD原本コピー。
- `assets/orcus_sword.png`: 前回PoC内の提供剣のコピー。再生成していない。
- `assets/asset_bounds.json`: 生成画像の実寸と切出し矩形。
- `fit-core.js`: 接合点・足元・握り位置と純粋な座標計算。
- `generated/`: ブラウザ確認スクリーンショット。

衣装は仮の共通服であり、兵種衣装・世界観・個人衣装として未採用。頭は生成による試作なので元の頭のピクセル完全抽出ではなく、髪・表情など細部に変化がある。厳密に個性を維持する最終素材では、原作者確認済みの頭素材へ差し替える必要がある。

## 確認と限界

```powershell
node prototypes/sd-battle-motion/shared-body/verify_fit.js
node prototypes/sd-battle-motion/shared-body/verify_pixels.js
node prototypes/sd-battle-motion/shared-body/verify_presets.js
node prototypes/sd-battle-motion/shared-body/verify_reference_ui.js
```

現行テストは1215通りの合成と675通りの元SD位置・大きさ、23画像の実寸、入力コピー11枚の同一性を検証。画素テストはマスクハッシュ、63通りの配色両端、alpha・保護画素・入力保持、元色復帰とグループ独立を検証する。記録テストは兵種カタログ一致・外見識別・履歴・読込v3/v4/v5・重複マージ・静止描画記述・不正値／素材IDを検証。UI単体テストは従来の接合／配色／PNG操作に加え、記録・呼出・再読込・JSON v5・取込の不正入力保護・ブラウザ保存失敗の退避・壊れた保存の保全・素材読み込みエラー／再試行を検証。単体テストは実画面の目視確認を代替しない。

履歴: 元SD比較の最初の追加時はブラウザ操作の自動承認レビューが利用制限で停止し、当時の実画面確認は未完了だった。今回の衣装比較で元SDの隣表示・透かし機能も確認した。`generated/child_preview.jpg` と `standard_preview.jpg` は旧段階の画面で、新しい衣装比較の証拠として扱わない。

静止画像だけを作成したため、APNG・攻撃連番はまだない。次に身体1系統・1つの片手剣攻撃を少数のキー姿勢で作り、姿勢ごとに頭の位置・角度と武器の位置・角度・前後順を付けて比較する。姿勢ごとに別々の頭や武器APNGを独立再生する設計にはせず、同じタイムラインに載せる。

今回の素材だけで全キャラに対応できるとは判断しない。頭サイズだけでは吸収しにくい肩幅・手足の長さ・体格は別の身体系統が必要。ロングヘア、極端な身長差、男女のシルエット差、盾や両手武器、背面姿勢は未検証。左右反転で眼帯や利き手も反転するため、厳密な左右非対称は別対応が必要。

まずは原作者が共通服・頭の大きさ・首のつながりを確認する。その後、身体1系統の攻撃を3人で共有して自然に見えるかを検証し、全キャラ・全兵種の量産へ進むか判断する。
